This guide optimizes a support-ticket triage agent end to end. The agent reads a customer
ticket and should answer with one line naming its category and priority. Its starting
prompt doesn't say that, so it starts out writing friendly paragraphs instead. You'll let the
optimizer rewrite the prompt and tune the temperature, then read what won and why. The run
takes about ten minutes and 120 rollouts.

## Install the SDK

The optimizer ships with the evals SDK behind the `optimization` extra, which adds numpy,
scipy, Optuna, and the Strands harness:

```bash
pip install 'strands-agents-evals[optimization]' strands-agents
```

Importing `strands_evals.optimization` without the extra raises an `ImportError` that names
this command.

The agent, the judge, and the default text rewriter all call Claude on Amazon Bedrock.
Configure AWS credentials with permission to invoke them: see the
[evals quickstart](../quickstart.md#configure-credentials). Refresh short-lived
credentials before a long run. Trials that fail on expired credentials are retried, never
scored, but they keep spending rollouts.

## Write the experiment

The optimizer judges every configuration with an ordinary
[experiment](../how-evaluation-works.md#what-an-evaluation-is-made-of): its cases are the
work the agent should do well, and its evaluators score how well it did. If you already
evaluate your agent, reuse that experiment. This guide builds a new one: twenty tickets,
each with the label it should get, and a rubric judge that scores the agent's line against
that label.

```python
from strands_evals import Case, Experiment
from strands_evals.evaluators import OutputEvaluator

TICKETS = [
    (
        "I was charged twice for order #4821, please refund the duplicate.",
        "billing",
        "high",
    ),
    (
        "My card was charged $250 but the order was cancelled yesterday.",
        "billing",
        "high",
    ),
    (
        "Can I get an invoice with my company's tax ID for last month's order?",
        "billing",
        "normal",
    ),
    ("My discount code SAVE10 didn't apply at checkout.", "billing", "normal"),
    ("Do you accept PayPal?", "billing", "low"),
    ("My package was marked delivered a week ago but never arrived.", "shipping", "high"),
    (
        "Can I change the delivery address on order #5520? It hasn't shipped yet.",
        "shipping",
        "normal",
    ),
    ("Tracking for order #6013 hasn't updated in five days.", "shipping", "normal"),
    ("Do you ship to Canada?", "shipping", "low"),
    ("How long does standard shipping usually take?", "shipping", "low"),
    ("The blender arrived cracked and leaking.", "returns", "high"),
    (
        "I returned my laptop three weeks ago and still haven't been refunded.",
        "returns",
        "high",
    ),
    ("The jacket I got is the wrong size. How do I exchange it?", "returns", "normal"),
    ("I want to return two unopened books from order #7710.", "returns", "normal"),
    ("What's your return policy for sale items?", "returns", "low"),
    ("Someone changed my account email and I can't log in.", "account", "high"),
    ("I see orders on my account that I didn't place.", "account", "high"),
    ("The password reset email never arrives.", "account", "normal"),
    ("How do I change the name shown on my profile?", "account", "low"),
    ("Can I turn off marketing emails?", "account", "low"),
]

triage_judge = OutputEvaluator(
    name="Triage",
    rubric=(
        "The response must be exactly one line: 'category: "
        "<billing|shipping|returns|account>, priority: <high|normal|low>'. Priority is "
        "high when the customer lost money, got a damaged item, or has an account "
        "security problem; low for a general question that needs no action; normal "
        "otherwise. Score 1.0 if the line matches the expected output, 0.5 if only the "
        "category matches or the format is off, and 0.0 otherwise."
    ),
)

experiment = Experiment(
    cases=[
        Case(
            name=f"ticket-{i:02d}",
            input=ticket,
            expected_output=f"category: {category}, priority: {priority}",
        )
        for i, (ticket, category, priority) in enumerate(TICKETS)
    ],
    evaluators=[triage_judge],
)
```

Every case needs a unique name, because candidates are compared case by case. Twenty cases
split into 8 for the search, 6 for picking the winner, and 6 for the final test.

## Declare what may change

Write the agent as a factory function and mark the parameters the optimizer may change.
The parameter defaults are the **baseline**: the agent you have today.

```python
from strands import Agent
from strands.models import BedrockModel
from strands_evals.optimization import Float, TextValue, tunable


@tunable(system_prompt=TextValue(), temperature=Float(0.0, 1.0))
def create_agent(system_prompt="You are a helpful support assistant.", temperature=0.9):
    return Agent(
        model=BedrockModel(
            model_id="us.anthropic.claude-haiku-4-5-20251001-v1:0",
            temperature=temperature,
        ),
        system_prompt=system_prompt,
        callback_handler=None,
    )
```

The optimizer rewrites the system prompt with a model (Claude Sonnet 5.5 on Amazon Bedrock
by default) that reads the agent's own conversations and the judge's reasons, and searches
the temperature alongside it. The rewriter works in a temporary folder through a confined
shell that isn't a sandbox, so run it on a machine without production credentials.

`@tunable` doesn't change how the function behaves when you call it: `create_agent()`
still returns the baseline agent. During a run, the optimizer builds a fresh agent for
every trial through this same function, so no state leaks between trials.

## Say what "better" means

Without an objective, the optimizer maximizes the mean of your evaluators. Here the goal is
the right label in as few words as possible:

```python
from strands_evals.optimization import Budget, Maximize, Minimize, Optimizer, WeightedSum

optimizer = Optimizer(
    experiment,
    create_agent,
    objective=WeightedSum(Maximize("Triage"), Minimize("output_tokens", scale=100)),
    budget=Budget(max_rollouts=120),
)
```

`scale=100` means a change of 100 output tokens weighs as much as the whole 0 to 1 Triage
range. Token counts come from the agent's traces, so you don't measure anything yourself.
A rollout is one case run once; the default budget is 500.

## Run it

```python
result = optimizer.run()
print(result.summary())
```

`run()` prints one line per step and writes everything to a run folder under
`.strands-evals/optimization/runs/`. Use `await optimizer.run_async()` inside an event
loop.

## Read what won

The summary answers three questions:

- **What ships.** Candidate 8, marked `*`, ranked highest on the validation cases the
  search never saw. The baseline scored about 0 on Triage: it answered every ticket with a
  paragraph. The champion scores 0.89 and writes about 13 tokens instead of 213.
- **Whether it holds up.** Yes. On the six test cases, which neither the search nor the
  pick ever read, Triage rose by 0.92 and output tokens fell by 184, both with intervals
  far from zero.
- **What to change.** One text value, the system prompt, and a slightly higher
  temperature.

The effects file tells you which of those changes did the work:

```python
for row in result.effects["effects"]:
    low, high = row["ci90"]
    print(f'{row["metric"]}: {row["key"]}={row["level"]} vs {row["reference"]}: '
          f'{row["mean"]:+.3g} [{low:+.3g}, {high:+.3g}]')
```

```text
# Example output (abridged):
Triage: rewritten:text=rewritten vs default: +0.743 [+0.678, +0.809]
Triage: temperature=(0.308522, 0.594614] vs (0.594614, 0.975872]: +0.00274 [-0.0324, +0.0379]
output_tokens: rewritten:text=rewritten vs default: -211 [-222, -200]
```

The rewritten prompt did all of it: +0.74 Triage and 211 fewer tokens. Temperature made
no difference, so the champion's `0.98` is where the search happened to be, not a
finding: keep your current value. See
[Reading the results](results.md#which-options-mattered) for the full effects table.

## Apply the result

Nothing in your code changed. The run folder holds what you need to apply by hand:

- `best.diff`: a unified diff of every changed text value, here the system prompt
- `best.values.json`: every changed number and choice, with its old and new value

The rewritten prompt, from `best.diff` (abridged):

```diff
--- system_prompt
+++ system_prompt
@@ -1 +1,20 @@
-You are a helpful support assistant.
+You are a support ticket triage classifier. Every user message is a customer ticket.
+Never answer it, give advice, ask questions, or greet. Only classify it.
+
+Output exactly one line, nothing else:
+category: <category>, priority: <priority>
+
+category (pick one, lowercase):
+- billing: charges, duplicate charges, payments, invoices, tax IDs, pricing
+- returns: returns, refunds, return policy, damaged/defective/wrong items, exchanges
+- account: login, password reset, profile/name/email changes, security
+- shipping: delivery status, lost/late packages, tracking, shipping address
+- product: product features, usage, availability, compatibility
+- other: anything that fits none of the above
+
+priority (pick one, lowercase):
+- high: money lost or at risk, damaged or broken goods, security/unauthorized access
+- normal: routine request with a specific problem to fix
+- low: general questions, policy inquiries, minor changes with no urgency
```

Review the rewrite before you copy it in. This one added two categories, `product` and
`other`, that none of the tickets use. They're harmless here, but you might drop them, or
keep them if your real tickets need somewhere to go. Then rerun your experiment on a few
fresh tickets to confirm.

The same run from a shell, with the experiment saved by
`experiment.to_file("experiment.json")` and `create_agent` in `agent.py`:

```bash
strands-evals optimize run experiment.json --agent agent.py:create_agent \
  --objective maximize:Triage --objective minimize:output_tokens:scale=100 \
  --max-rollouts 120
```
