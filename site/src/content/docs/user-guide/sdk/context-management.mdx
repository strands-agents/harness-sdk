As conversations grow, your agent's context window fills with messages, tool results, and system prompts. Without management, this leads to token limit errors, degraded performance, and loss of relevant information.

The SDK ships context management that works out of the box. Pick a mode and the SDK wires up an ordered strategy pipeline with tuned defaults.

[Conversation managers](./agents/conversation-management) and [ContextOffloader](./plugins/context-offloader) remain supported. See [Migrating to the strategy API](#migrating-to-the-strategy-api) for optional migration examples.

## Quick start

Pass <Syntax py='context_manager="auto"' ts='contextManager: "auto"' /> and the SDK manages context in the background:

<Tabs>

```python

agent = Agent(context_manager="auto")
```

## How it works

The <Syntax py="context_manager" ts="contextManager" /> parameter is a first-class agent parameter, not a plugin. It creates a `ContextManager` that owns all context reduction for the agent.

The ContextManager runs strategies as an ordered pipeline. Each strategy sees the output of the previous one. The SDK always appends an emergency truncation strategy as the final step, which only fires when the window is still overflowing after all other strategies have run.

A stash stores all message content on arrival as JSON, before any strategy acts. Truncated or summarized content is preserved and retrievable on demand through the `retrieve_context` tool, registered by default.

When <Syntax py="context_manager" ts="contextManager" /> is set, any co-provided <Syntax py="conversation_manager" ts="conversationManager" /> is ignored. The ContextManager owns overflow recovery and proactive compression internally.

## Choosing a mode

| Value | Behavior |
|-------|----------|
| `"auto"` | Background compression with tuned defaults. No model involvement. |
| `"agentic"` | Experimental. Model-driven: the model manages its own context. |
| Custom config | Full control over the strategy pipeline, targets, and conditions. |
| `false` | No context management. Overflow errors propagate directly. |

See [Built-in Modes](./context-management/built-in-modes) for details on `"auto"` and `"agentic"`. See [Custom Strategies](./context-management/custom-strategies) to build your own pipeline. See [Strategy Presets](./context-management/presets) for named shorthand configurations.

## Storage backends

The `ContextManager` uses in-memory stash storage by default. Content does not persist across process restarts. Provide a durable storage backend when the stash needs to survive restarts:

<Tabs>
<Tab label="Python">

```python
from strands.storage import LocalFileStorage, S3Storage

# Local filesystem
stash = {"storage": LocalFileStorage("./artifacts/")}

# S3, using ambient AWS credentials
stash = {
    "storage": S3Storage(
        "my-bucket", prefix="agent-stash/",
    ),
}
```

## Limitations

**Stateful models.** Stateful models manage conversation state server-side. Setting <Syntax py="context_manager" ts="contextManager" /> with a stateful model raises an error.

**Repository session managers (Python).** Use `SnapshotSessionManager` with <Syntax py="context_manager" ts="contextManager" />. Repository-based session managers, such as `FileSessionManager`, `S3SessionManager`, and the AgentCore Memory session manager, do not persist context reductions. A restored agent reloads the full history and runs reduction again, so summarization re-runs on every restore. The SDK warns when you combine the two.

**Reasoning content.** Context reduction does not preserve reasoning (thinking) blocks from the messages it reduces. Summarization leaves reasoning out of the summary, because a reasoning block's signature is only valid in the conversation that produced it, and removing messages removes their reasoning too. The stash does not store reasoning, so the retrieval tool cannot recover it. Offloading never edits reasoning blocks in place.

**Preserved thinking (Claude Opus 5.5, Claude Fable 5.1, Claude Sonnet 5.5).** On these models, a thinking block stays valid only while everything before it is unchanged. A reduction edits earlier history, so it invalidates the thinking blocks in every later message, not only in the reduced ones. If the API rejects the request, the Anthropic and Bedrock model providers retry with `prefix_mismatch_behavior: "drop_block"`, and the API drops the invalidated blocks. The retry requires adaptive thinking (`{"type": "adaptive"}`). After a reduction, the model continues without its earlier reasoning.

## Migrating to the strategy API

If you currently use `SummarizingConversationManager`, `ContextOffloader`, or `conversation_manager`, use these examples as starting points. Review the strategy conditions and preservation settings for your workload because the strategy API does not map one-to-one to every existing option.

<Tabs>
<Tab label="Python">

| Before | After |
|--------|-------|
| `SummarizingConversationManager(...)` | `Offload.summarize("*").when(utilization=0.85, preserve_recent=4)` |
| `ContextOffloader(max_result_tokens=2500, preview_tokens=500)` | `Offload.truncate("tool_results", {"preview_tokens": 500}).when(threshold=2500)` |
| `SlidingWindowConversationManager(...)` | No exact equivalent. Use `Offload.drop` or `Offload.truncate` with utilization and preservation conditions. |
| `context_manager="auto"` | Unchanged |

</Tab>
<Tab label="TypeScript">

| Before | After |
|--------|-------|
| `new SummarizingConversationManager(...)` | `Offload.summarize("*").when({ utilization: 0.85, preserveRecent: 4 })` |
| `new ContextOffloader({ maxResultTokens: 2500, previewTokens: 500 })` | `Offload.truncate("toolResults", { previewTokens: 500 }).when({ threshold: 2500 })` |
| `new SlidingWindowConversationManager(...)` | No exact equivalent. Use `Offload.drop` or `Offload.truncate` with utilization and preservation conditions. |
| `contextManager: "auto"` | Unchanged |

</Tab>
</Tabs>

### Updating experimental imports

`ContextManager`, `Offload`, and their configuration types are exported from the main package. The experimental import paths still work, but they are deprecated and will be removed in v1.63.0 (Python) and v1.23.0 (TypeScript). In Python, they emit a `DeprecationWarning`.

<Tabs>
<Tab label="Python">

| Before | After |
|--------|-------|
| `from strands.experimental.context_manager import ContextManager, Offload` | `from strands.context_manager import ContextManager, Offload` |

</Tab>
<Tab label="TypeScript">

| Before | After |
|--------|-------|
| `import { ContextManager, Offload } from '@strands-agents/sdk/experimental'` | `import { ContextManager, Offload } from '@strands-agents/sdk'` |

</Tab>
</Tabs>
