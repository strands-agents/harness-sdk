Vended tools are pre-built tools included directly in the Strands Harness SDK for common agent tasks like file operations, shell commands, HTTP requests, and persistent notes.

They ship as part of the SDK package and are updated alongside it. See [Versioning & Maintenance](#versioning--maintenance) for how changes are communicated and what level of backwards compatibility they maintain.

## Quickstart

Each tool is imported from its own subpath under `@strands-agents/sdk/vended-tools`, with no additional packages required:


## Available tools

| Tool | Description | Supported in |
|------|-------------|--------------|
| [Edit](#edit) | Make in-place changes to a text file | Python |
| [File Editor](#file-editor) *(deprecated)* | View, create, and edit files | Python, TypeScript (Node.js) |
| [Read](#read) | Read a file as numbered text or a media block | Python |
| [Write](#write) | Create or overwrite a text file with the full provided content | Python |
| [HTTP Request](#http-request) | Make HTTP requests to external APIs | Python, TypeScript (Node.js 22+, browsers) |
| [Notebook](#notebook) | Manage persistent text notebooks | Python, TypeScript (Node.js, browsers) |
| [Bash](#bash) | Execute shell commands with persistent sessions | Python, TypeScript (Node.js, Unix/Linux/macOS) |
| [MCP Router](#mcp-router) | Connect to Model Context Protocol servers on a developer-set allowlist | Python, TypeScript (Node.js) |
| [Sleep](#sleep) | Pause execution for a bounded, cancellable duration | Python, TypeScript (Node.js, browsers) |
| [Handoff to User](#handoff-to-user) | Pause the agent loop and surface a message to the user | Python, TypeScript (Node.js, browsers) |
| [Stop](#stop) | Gracefully end the agent loop when the task is complete | Python, TypeScript (Node.js, browsers) |
| [Web Fetch](#web-fetch) | Fetch a URL and return cleaned markdown for a model to read | Python, TypeScript (Node.js) |
| [A2A Client](#a2a-client) | Discover and send messages to remote A2A-protocol agents | Python, TypeScript (Node.js, browsers) |
| [Python REPL](#python-repl) | Execute Python code through the agent's sandbox | Python, TypeScript (Node.js, Unix/Linux/macOS) |
| [Subagent](#subagent) | Delegate a self-contained task to a child agent | Python, TypeScript (Node.js, browsers) |
| [Swarm](#swarm) | Spin up a team of agents that collaborate via the swarm pattern | Python, TypeScript (Node.js, browsers) |
| [Graph](#graph) | Run a team of sub-agents as a directed acyclic graph designed by the model | Python |

### Edit

Lets your agent make surgical, in-place changes to a text file by replacing an exact, unique string (`old_str` must appear in the file exactly once).

The `edit` tool pairs with the `read` and `write` vended tools and supersedes `file_editor`. Available in Python today.

:::caution[Security Warning]
This tool writes files at arbitrary absolute paths with the full permissions of the process. Only use with trusted input and consider running in a [sandboxed environment](../sandbox/index.mdx) for production.
:::

**Example:**

<Tabs>
<Tab label="Python">

```python
from strands import Agent
from strands.vended_tools import edit

agent = Agent(tools=[edit])
agent("In /tmp/hello.txt, replace 'world' with 'Strands'.")
```

</Tab>
</Tabs>

### Read

Reads a file through the agent's sandbox. Text files return `cat -n` style numbered lines so the model can cite `path:line`, with `offset` and `limit` for paging through large files. Images (png/jpg/jpeg/gif/webp) and binary documents (pdf/doc/docx/xls/xlsx) return as media content blocks when the model accepts media; otherwise `make_read(media=False)` returns a short text placeholder describing the file.

_Supported in: Python._

:::caution[Security Warning]
This tool reads files at arbitrary absolute paths with the full permissions of the process. Only use with trusted input and consider running in a [sandboxed environment](../sandbox/index.mdx) for production.
:::

**Example:**

<Tabs>
<Tab label="Python">

```python
from strands import Agent
from strands.vended_tools import read

agent = Agent(tools=[read])
agent("Read /etc/hosts and summarize what it maps.")
```

### Write

Lays down the full content of a text file in one shot — creating it or overwriting whatever is there.

The confirmation returned to the model is of the form `Wrote <N> lines to <path>.`, where `N` is the number of `\n`-separated entries in the content (so content ending with a newline reports one more entry than text lines, and empty content reports zero). Available in Python today; TypeScript ships in a follow-up.

:::caution[Security Warning]
This tool writes files at arbitrary absolute paths with the full permissions of the process. Only use with trusted input and consider running in a [sandboxed environment](../sandbox/index.mdx) for production.
:::

**Example:**

```python
from strands import Agent
from strands.vended_tools import write
```

### Bash / shell

Lets your agent run shell commands and act on the output. The two SDKs expose
different tools here:

- **TypeScript `bash`** spawns a persistent `bash` process on the host. Shell state (variables, working directory, exported functions) persists across invocations within the same session, so the agent can build up context incrementally. Sessions can be restarted to clear state.
- **Python `shell`** (and TypeScript's `makeShell`) routes each command through the agent's [Sandbox](../sandbox/index.mdx) and is stateless: every call runs in a fresh shell, so variables and the working directory do not carry over. The sandbox decides the interpreter (`sh` locally and in Docker, the remote login shell over SSH), so use portable POSIX syntax.

_Supported in: Node.js on Unix/Linux/macOS (TypeScript), all platforms (Python)._

:::caution[Security Warning]
These tools execute arbitrary shell commands. Without a [Sandbox](../sandbox/index.mdx), commands run with the full permissions of the process. Only use with trusted input and consider running in a [sandboxed environment](../sandbox/index.mdx) for production.
:::

### Sleep

Pauses the agent for a bounded number of seconds. Cancelling the enclosing
invocation aborts the sleep immediately rather than waiting for the full
duration, so a long timer never ties up a session the caller has moved on from.

_Supported in: Node.js, modern browsers (TypeScript); all platforms (Python)._

The maximum duration is configurable at construction (default: 60 seconds) and
cannot be raised by the model. Negative, `NaN`, infinite, non-numeric, and
boolean durations are rejected at the tool boundary.

### Handoff to User

Lets the model pause the agent loop and surface a message to the user for
human-in-the-loop input. Use this when the agent needs explicit confirmation,
additional information, or user approval before proceeding.

_Supported in: Node.js, modern browsers (TypeScript); all platforms (Python)._

:::note[Bidirectional streaming not supported]
`handoff_to_user` relies on the interrupt/resume mechanism, which requires the agent loop to fully halt and restart. It cannot be used inside bidirectional streaming sessions, where the loop runs continuously without a clean pause point.
:::

The loop halts with a `stop_reason` / `stopReason` of `"interrupt"` and the message is available
on the interrupt's `reason` field in `AgentResult.interrupts`. Resume the agent
by passing back an `interruptResponse` content block with the interrupt ID and
the user's reply; the tool then returns that reply as its result and the model
continues. To recognize a handoff interrupt, match its `name` against the exported
`HANDOFF_INTERRUPT_NAME` constant.

:::note[Combining with HumanInTheLoop]
`HumanInTheLoop()` requires approval for every tool by default, so pairing it
with `handoff_to_user` prompts the user twice — once to approve the call, then
again to answer it. Allow-list the tool with
`HumanInTheLoop(allowed_tools=["handoff_to_user"])` / `new HumanInTheLoop({ allowedTools: ["handoff_to_user"] })`
so only the handoff itself prompts.
:::

**Example:**

<Tabs>
<Tab label="TypeScript">

```typescript
--8<-- "user-guide/sdk/tools/vended-tools-imports.ts:handoff_to_user_import"

--8<-- "user-guide/sdk/tools/vended-tools.ts:handoff_to_user_example"
```

</Tab>
<Tab label="Python">

```python
from strands import Agent
from strands.vended_tools.handoff_to_user import HANDOFF_INTERRUPT_NAME, handoff_to_user

agent = Agent(
    tools=[handoff_to_user],
    system_prompt=(
        "Before deleting any files, call handoff_to_user to confirm with the user."
    ),
)

print(interrupt.reason)

resumed = agent([
    {
        "interruptResponse": {
            "interruptId": interrupt.id,
            "response": "confirmed",
        }
    }
])
```

### Stop

Lets the model gracefully end the agent loop with an optional final message. The default loop already terminates when the model returns without any tool call; the stop tool is useful when you want an explicit "I am done" affordance, when a workflow enforces that termination is a deliberate model decision, or when a sub-agent needs to signal completion back to a coordinator via the loop's last assistant message.

_Supported in: Node.js, modern browsers (TypeScript); all platforms (Python)._

This is a cooperative stop, not an abort. Any other tools the model requested in the same turn still run to completion; the loop halts after that batch without calling the model again. The final message defaults to a 4096-character cap; pass `max_message_length` / `maxMessageLength` to `make_stop` / `makeStop` when a longer summary is legitimate.

The two SDKs shim onto different loop-termination primitives, which produces a
small difference in the final `AgentResult`'s stop reason. TypeScript halts via
`AfterToolsEvent.endTurn` and returns `stopReason: "endTurn"`. Python halts via
`agent.cancel(message=..., after_current_tools=True)` and returns
`stop_reason: "cancelled"`. In both cases the stop text is appended as the last
assistant message.

### Web fetch

Fetches an HTTP(S) URL and returns its content. Two modes are available,
configured at construction time via `make_web_fetch` / `makeWebFetch`:

- **`agentic`** (default): HTML is converted to markdown and passed to an
  analyst agent that answers a `prompt`, so the full page never enters the
  main agent's context. Use when targeted answers are needed about potentially
  large pages.
- **`markdown`**: HTML is converted to clean markdown with scripts, styles,
  and noise stripped. Use when the agent needs full pages for reasoning.

The `max_bytes` / `maxBytes` parameter caps the HTTP response size (default 5 MiB);
`max_content_chars` / `maxContentChars` caps the extracted content delivered to the model or
analyst (default 50,000 characters). For `mode='agentic'` / `mode: 'agentic'`,
the factory also accepts a `model` for the analyst; <Syntax py="agent.aux_model" ts="agent.auxModel" />
is used when none is supplied.

The Python tool delegates all networking to an `httpx.AsyncClient`. Use the
`make_web_fetch` factory to supply a pre-configured client with custom
timeouts, redirects, proxies, or caching.

_Supported in: Node.js (TypeScript); Python (all platforms)._

:::note[Install required]
<Tabs>
<Tab label="Python">
`web_fetch` requires the optional `web-fetch` extra:

```bash
pip install 'strands-agents[web-fetch]'
```
</Tab>
<Tab label="TypeScript">
HTML conversion requires the optional `turndown` peer dependency:

```bash
npm install turndown
```
</Tab>
</Tabs>
:::

:::note[Security posture]
Web fetch accepts only `http://` and `https://` URLs and caps response bodies
at 5 MiB by default. Egress control belongs at the layer that encapsulates the
agent (a sandbox, microVM, or network policy) where it can be enforced
consistently across all tools, including `shell`.
:::

### MCP Router

Lets your agent connect to Model Context Protocol servers at runtime, list the tools they expose, invoke one, and disconnect. The factory takes a developer-set allowlist of server configurations; the model can only initiate connections to servers on that list.

The tool exposes five commands: `connect` (opens a named connection to an allowlisted server using a `connection_id`), `list_connections` (returns all open connection IDs for the current agent), `list_tools` (returns the tools the server exposes), `call_tool` (invokes a tool by name), and `disconnect` (closes a connection).

Connections are scoped per agent and persist across invocations on the same agent instance. A connection is closed when the model calls `disconnect` explicitly, or when the agent is garbage collected. The connection remains open otherwise.

_Supported in: Node.js (TypeScript); all platforms (Python)._

:::caution[Security Warning]
The allowlist controls which servers the model may connect to. For HTTP servers, treat this like any network request — egress control belongs at the encapsulation layer. For stdio servers, the allowlisted command is spawned as a local process with access to the host filesystem, environment variables, and network. Only allowlist commands you would run directly on the host.
:::

### A2A Client

Lets your agent discover and communicate with remote [A2A (Agent-to-Agent) protocol](https://google.github.io/A2A/) agents.
Two operations are available:

- **`discover`** — fetches the agent card from a remote A2A endpoint and returns its capabilities, name, description, and skills.
- **`send_message`** — sends a text message to a remote A2A agent and returns the response.

The tool is stateless: a fresh `A2AAgent` is created on every call using the
per-endpoint configuration. Use `make_a2a_client` / `makeA2AClient` to control which endpoints the model may contact, with
per-endpoint authentication, and to tune size limits.

_Supported in: Python, TypeScript (Node.js, browsers)._

:::note[Install required]
<Tabs>
<Tab label="Python">
`a2a_client` requires the optional `a2a` extra:

```bash
pip install 'strands-agents[a2a]'
```
</Tab>
<Tab label="TypeScript">
Requires the optional `@a2a-js/sdk` peer dependency:

```bash
npm install @a2a-js/sdk
```
</Tab>
</Tabs>
:::

:::caution[Endpoint security]
`allowed_endpoints` / `allowedEndpoints` is required and checked before any network connection is made, but it only gates the agent-card fetch. `send_message` is delivered to the `url` in that card, which may point to a different host, and HTTP redirects are not checked either. For full egress control, enforce it at the network layer.
:::

### Python REPL

Runs model-generated Python through the agent's [sandbox](../sandbox/index.mdx) by calling `sandbox.execute_code(code, "python3")` (`sandbox.executeCode(code, 'python3')` in TypeScript). It returns `output` (stdout), `error` (stderr, including tracebacks), and `exit_code`. Each call runs in a fresh interpreter, so variables, imports, and definitions do not persist across calls. Files written to the sandbox filesystem do persist, so the model can checkpoint intermediate results to disk and load them in a later call.

_Supported in: Node.js on Unix/Linux/macOS (TypeScript), Python._

:::caution[Security Warning]
This tool executes arbitrary Python code. Without a [Sandbox](../sandbox/index.mdx), code runs with the full permissions of the process. Only use with trusted input and consider running in a [sandboxed environment](../sandbox/index.mdx) for production.
:::

### Subagent

Delegates a self-contained task to a child agent that runs in its own context and returns a final report. Use it when a subtask would otherwise flood the parent's context with intermediate work and you only need the conclusion. The model writes the task each time it calls the tool; the child cannot ask follow-up questions, so the task must include all the context it needs.

The <Syntax py="make_subagent" ts="makeSubagent" /> factory uses [axis policies](#axis-policies) to control what the model can configure on each child.
The configurable axes are `instructions`, `tools`, `model`, and `context`. The parent also passes a task to the child.

By default, the child sees only the task (<Syntax py='context=Fixed("none")' ts="context: new Fixed('none')" />), but you can share the parent's conversation by setting `context` to a `Choice` over `"none"`, `"all"` (full history including tool calls), and `"no_tools"` (text turns only). When a non-`"none"` option is available, the model can also pass `last_messages` to limit how many parent messages to share.

_Supported in: Python, TypeScript (Node.js, browsers)._

### Graph

Lets your agent design and run a team of sub-agents as a [Graph](../multi-agent/graph.mdx). The model supplies a `task`, a list of `nodes` (each with a unique `name` and its own `instructions`), and `edges` that order them. Nodes with no upstream nodes start in parallel, and each node receives its upstream outputs.

Nodes inherit the caller's model and tools, including MCP tools, except graph tools. Child
interrupts pause the tool call and resume with the user's response. An interrupted graph
is saved in the parent agent's interrupt state, so it can resume after the parent is
restored from a snapshot or session. By default, a call times out after 900 seconds and
each node after 300 seconds. A running graph cannot be cancelled from the parent agent.

**Example:**

```python
from strands import Agent
from strands.vended_tools import graph, http_request

agent = Agent(tools=[graph, http_request])
agent("Research three competing vector databases in parallel, then write a comparison table.")
```

Use `make_graph` to set limits (`max_nodes`, `max_edges`, `max_node_executions`,
`execution_timeout`, `node_timeout`), build each node agent yourself with `builder`, or control
what the model configures on each node with [axis policies](#axis-policies) over `instructions`,
`tools`, and `model`.

**Custom configuration:**

```python
from strands import Agent
from strands.multiagent import Choice, Preset
from strands.vended_tools import file_editor, http_request, make_graph

team = make_graph(
    presets={
        "researcher": Preset(
            instructions="Gather facts from the web and cite every source.",
            tools=["http_request"],
            description="Finds and summarizes sources.",
        ),
        "writer": Preset(
            instructions="Turn upstream findings into clear prose.",
            tools=["file_editor"],
            description="Drafts the final document.",
        ),
    },
    tools=Choice(["http_request", "file_editor"], multiple=True),
    max_nodes=6,
    max_edges=10,
    execution_timeout=600,
    node_timeout=120,
)
agent = Agent(tools=[team, http_request, file_editor])
```

## Axis policies

Some vended tools let the model configure child agents at runtime. Axis policies control how much freedom the model has over each parameter. Import them from <Syntax py="strands.multiagent" ts="@strands-agents/sdk/multiagent" />.

| Policy | Effect | Model sees a parameter? |
|--------|--------|------------------------|
| <Syntax py="Inherit()" ts="new Inherit()" /> | Child inherits the parent's value | No |
| <Syntax py="Fixed(value)" ts="new Fixed(value)" /> | Developer pins the value | No |
| <Syntax py="Open()" ts="new Open()" /> | Model writes a free-form value | Yes (string) |
| <Syntax py="Choice([...], multiple=True)" ts="new Choice([...], true)" /> | Model picks from a set | Yes (enum) |

Use `Option` inside a `Choice` to map model-facing names to runtime values. Bundle axis defaults into a `Preset` that the model selects via `agent_type`. When the model omits both `agent_type` and `instructions`, the child uses <Syntax py="default_preset" ts="defaultPreset" />, or the first preset if none is set.

Tools that accept axis policies use a default builder to turn resolved specs into child agents. By default, it produces child agents that inherit the parent's tools, model, and interventions, so a child's tool calls go through the same approval and authorization checks as the parent's. Each child gets <Syntax py='context_manager="auto"' ts="contextManager: 'auto'" /> (unless its model is stateful) in place of the parent's context-management tools, and accesses the parent's long-term memory through inherited memory tools.

To replace the default builder, pass any callable that takes an `AgentSpec` and returns an `Agent`. A custom builder decides everything the child inherits, including interventions.
