[Decisions API][decisions-api] serves decision models at decisionapi.net, with model
identifiers such as `~typesafe/jev-latest`. `DecisionsAPIDecisionModel` sends your
questions there and returns the same result as every other
[decision model](index.mdx), plus a probability for each label and a confidence for
each answer. By default it asks TypeSafe's Jev model.

Choose it when you have a Decisions API key. If you have a TypeSafe key, use
[`TypeSafeDecisionModel`](typesafe.mdx) instead: it calls Jev on TypeSafe directly,
reports the exact Jev version that answered, and isn't capped at eight questions per
call.

Follow the [quickstart](../quickstart.mdx) to ask your first questions. Swap in
`DecisionsAPIDecisionModel` and the rest of the code stays the same.

## Credentials

Get an API key from Decisions API and set it in your environment:

```bash
export JEV_API_KEY="your-api-key"
```

`DecisionsAPIDecisionModel` reads `JEV_API_KEY` when you construct it. The variable
holds a decisionapi.net key, not a TypeSafe key, despite the name. To pass the key
directly, set <Syntax py="api_key" ts="apiKey" />. The constructor raises an error when
neither is set.

## Configuration

| Option | Description |
| --- | --- |
| <Syntax py="api_key" ts="apiKey" /> | Decisions API key. Defaults to `JEV_API_KEY`. |
| <Syntax py="model_id" ts="modelId" /> | Decisions API model identifier. Defaults to `~typesafe/jev-latest`. |
| <Syntax py="default_min_confidence" ts="defaultMinConfidence" /> | Confidence below which an answer comes back `Uncertain`, in `[0.0, 1.0]`. Defaults to `0.5`. See [Confidence and uncertainty](#confidence-and-uncertainty). |
| <Syntax py="http_client" ts="fetch" /> | How the request is sent. See [Timeouts and connections](#timeouts-and-connections). |

See the API reference for [Python][model-api] or [TypeScript][model-api-ts] for all
constructor options.

## Ask questions

This example asks two questions about a support message and prints each answer with
its confidence:

<Tabs>
<Tab label="Python">

```python
import asyncio

from strands.decisions import DecisionsAPIDecisionModel

message = "I was charged twice for order 1182. Please refund one charge today."


async def main():
    decisions = DecisionsAPIDecisionModel()
    result = await decisions.ask(
        message,
        {
            "urgent": {
                "question": "Does the customer need help today?",
                "choices": "boolean",
            },
            "team": {
                "question": "Which team should handle this message?",
                "choices": ["billing", "shipping", "technical"],
            },
        },
    )
    confidence = result.metadata.confidence
    print(result.answers["urgent"], f"{confidence['urgent']:.2f}")
    print(result.answers["team"], f"{confidence['team']:.2f}")
    print(result.metadata.model_id)


asyncio.run(main())

# Typical output:
# True 0.90
# billing 1.00
# ~typesafe/jev-latest
```

Decisions API doesn't say which model version answered, so the result reports the model
you requested, such as `~typesafe/jev-latest`, unless the response names one. When you
need to trace each decision to a model version, use
[`TypeSafeDecisionModel`](typesafe.mdx).

Decisions API accepts at most eight questions per call. Split a larger set across
several `ask` calls.

## Confidence and uncertainty

The model reports a confidence for every answer. An answer below the minimum comes back as
`Uncertain`, and `metadata.confidence` and `metadata.probabilities` still show what the
model leaned toward. [Confidence](../questions.mdx#confidence) explains how it's measured.

The default minimum of 0.5 suits most routing and triage questions. For a question
where a wrong answer costs more than asking a person, raise the minimum on that
question alone: set its `uncertainty` to
<Syntax py='{"min_confidence": 0.8}' ts="{ minConfidence: 0.8 }" />.

## Timeouts and connections

<Tabs>
<Tab label="Python">

With no client configured, each call opens an `httpx.AsyncClient` with a 30-second
timeout, which httpx applies to each phase, such as connecting or reading. Pass your own
client to reuse connections across decisions, change the timeout, or add headers. You
own the client, so close it when you're done:

```python
import asyncio

import httpx

from strands.decisions import DecisionsAPIDecisionModel

messages = ["My package never arrived.", "The app crashes when I log in."]


async def main():
    # Reuse one connection pool, and give up if connecting or any read takes over
    # five seconds
    async with httpx.AsyncClient(timeout=httpx.Timeout(5.0)) as client:
        decisions = DecisionsAPIDecisionModel(http_client=client)
        for message in messages:
            result = await decisions.ask(
                message,
                {
                    "team": {
                        "question": "Which team should handle this message?",
                        "choices": ["billing", "shipping", "technical"],
                    },
                },
            )
            print(result.answers["team"])


asyncio.run(main())

# Typical output:
# shipping
# technical
```

</Tab>

## Errors

Beyond the [validation errors](../questions.mdx#validation), `ask` raises:

| Error | When |
| --- | --- |
| <Syntax py="ModelThrottledException" ts="ModelThrottledError" /> | Decisions API is throttling or temporarily unavailable (HTTP 429, 503, or 529). Retry with backoff. |
| <Syntax py="ContextWindowOverflowException" ts="ContextWindowOverflowError" /> | The request is too large (HTTP 413). Shorten the input, such as by sending only the latest messages of a conversation. |
| <Syntax py="httpx.HTTPStatusError" ts="ModelError" /> | Any other non-2xx response, such as HTTP 401 for an invalid API key. |
| <Syntax py="httpx.TransportError" ts="ModelError" /> | <Syntax plain py="The request didn't complete, because of a network failure or a timeout." ts="The request failed before the response arrived, because of a network failure or a timeout. A failure after that raises the underlying error." /> |
| <Syntax py="StructuredOutputException" ts="ModelError" /> | Decisions API returned a response the decision model can't read, or reported an error inside a successful response. |
| <Syntax py="ValueError" ts="Error" /> | The request has more than eight questions. |

Decisions API can report a failure inside an HTTP 200 response, as a non-zero error
`code` with a message. The decision model raises it with both, rather than returning a
result with no answers.

The throttling and context window errors keep the HTTP failure as their cause.
<Syntax
  plain
  py="Read its status code from the cause's response."
  ts="Both extend ModelError, so check for them before you check for ModelError."
/>
