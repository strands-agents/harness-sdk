Every `ask` call that passes validation records an OpenTelemetry span, whichever
decision model answers it.
With [tracing](../observability-evaluation/traces.mdx) set up, you see each decision
next to the agent's model and tool calls. When a tool asks a decision model, the
decision span nests under that tool call's span. The span reports the tokens of that one
decision; [Decisions in an agent](agents.mdx#token-usage) covers adding them to the
agent's request.

## Decision span

The span is named `decision`. It records everything as span attributes:

| Attribute | Value |
| --- | --- |
| `gen_ai.operation.name` | `decision` |
| `gen_ai.decision.questions` | The question ids, as a list. |
| `gen_ai.decision.answers` | The answers as a JSON string, keyed by question id. An `Uncertain` answer appears as `{"uncertain": true}`, with its reason when there is one. |
| `gen_ai.decision.latency_ms` | Time the decision model spent on the call, in milliseconds. |
| `gen_ai.usage.input_tokens` | Input tokens, when the decision model reports usage. |
| `gen_ai.usage.output_tokens` | Output tokens, when the decision model reports usage. |

The question ids are set when the span starts, so every decision span has them. The
answers, latency, and token counts are set only when the decision model returns.

## Failed decisions

When the decision model raises, the span ends with an error status and records the
exception. It keeps the question ids, so you can see which questions failed. Invalid
questions, or an invocation context the SDK didn't create, raise before the span
starts, so they record no span. The question text and the input aren't recorded.
