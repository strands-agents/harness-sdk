Pause the agent before it acts and let a person approve, edit, or reject a tool call. The `HumanInTheLoop` intervention handler adds this oversight without custom interrupt logic: pass it to `interventions` and choose how to collect the human's response.

## How It Works

The handler uses the [`confirm` action](./index.mdx) to pause for human input. It builds on the SDK's [interrupt mechanism](../../interrupts) but abstracts away the manual interrupt/resume loop when you provide an `ask` option.

```mermaid
flowchart LR
    A[Tool call] --> B{Allowed?}
    B -->|Yes| C[Execute]
    B -->|No| D{Trusted?}
    D -->|Yes| C
    D -->|No| G{Classifier?}
    G -->|Safe| C
    G -->|Risky/None| E{Human approves?}
    E -->|Yes| C
    E -->|No| F[Cancel]
```

## Usage

Choose how to collect the human's response:

| Mode | When to use |
|------|-------------|
| Interrupt/resume (default) | Stateless deployments that persist state between requests |
| `"stdio"` | CLI applications where the user types at a terminal |
| Custom callback | Web UIs, Slack bots, or other async interfaces |

### Interrupt/Resume Mode (Default)

Without an `ask` option, the handler raises an interrupt and the agent pauses. The caller presents the interrupt to the user, collects their response, and resumes the agent. This is the same [interrupt/resume pattern](../../interrupts#hooks) used throughout the SDK. For stateless deployments, combine with a [session manager](../session-management) to persist state between requests.

## Configuration

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| <Syntax py="allowed_tools" ts="allowedTools" /> | <Syntax py="list[str]" ts="string[]" /> | <Syntax py="None" ts="undefined" /> | Tools that bypass approval. Supports `"*"` (all) and `"!tool_name"` (negation). |
| `classifier` | <Syntax py="bool, LLMClassifierConfig, or callable" ts="boolean, LlmClassifierConfig, or function" /> | <Syntax py="None" ts="undefined" /> | LLM risk classifier. `True` for built-in defaults, config object for custom prompt/model, or a custom function. |
| <Syntax py="enable_trust" ts="enableTrust" /> | <Syntax py="bool" ts="boolean" /> | <Syntax py="False" ts="false" /> | When enabled, trust responses are remembered for the session. |
| <Syntax py="evaluate_trust" ts="evaluateTrust" /> | Function | Accepts `"t"` or `"trust"` | Custom validator for trust responses. Only evaluated when trust is enabled. |
| `evaluate` | Function | Accepts <Syntax py='True, "y", or "yes"' ts="true, 'y', or 'yes'" /> | Custom validator for approval responses. |
| `ask` | <Syntax py='Function or "stdio"' ts="Function or 'stdio'" /> | <Syntax py="None" ts="undefined" /> | Pass a function for custom UIs, `"stdio"` for CLI prompting, or omit for interrupt/resume. |

### Trust Mode

When trust is enabled, a human can respond with `'t'` or `'trust'` to approve the current tool call AND remember that decision for the rest of the session. Subsequent calls to the same tool skip the prompt entirely. Trust works in all modes: interrupt/resume, stdio, and custom callbacks.

Trust state is stored in <Syntax py="agent.state" ts="agent.appState" /> and persists across turns within a session but resets when the agent is re-created. Negated tools (`"!tool_name"`) cannot be trusted and always prompt.

## When to Use

Use `HumanInTheLoop` when you want tool-level approval gating with minimal code: it handles allow-lists, trust, and collection mode out of the box. Use [raw interrupts](../../interrupts) when you need full control: custom interrupt shapes, multi-step interactions, or workflows beyond simple approve/deny.
