Use these answers when choosing SDK components or preparing an agent for
production. Each answer links to the relevant configuration or API guide.

## Should I use Strands harness or the Strands Harness SDK?

[Strands harness](../harness/) gives you a complete agent harness with
opinionated defaults that you can override. The Strands Harness SDK gives you
the agent loop and the individual components for building a harness, including
tools, memory, sessions, plugins, and interventions.

Use Strands harness when its defaults fit your application. Use the SDK when you
want to choose the components or control orchestration yourself. Strands harness
is built on the SDK, so you can
[replace individual components later](../harness/composing-with-sdk/).

## Can I keep my current model when I move to Strands?

You can keep the model when its provider supports the capabilities your agent
needs. The agent loop is separate from the
[model provider](./model-providers/), so you can change providers without
restructuring the agent. For example, an application moving from OpenAI can keep
its OpenAI model and credentials while using Strands for orchestration.

You still need to adapt tool definitions, state handling, and multi-agent
behavior to the Strands APIs. The
[OpenAI migration guide](../migrate/openai/) maps those concepts and explains
where the behavior does not translate directly.

## Should I use Python or TypeScript?

Use the SDK that matches your application's runtime. Both implement the core
agent loop and support tools, MCP tools, streaming, structured output, sessions,
and the main multi-agent patterns.

Support for features and providers varies between the SDKs. Bidirectional agents
are currently Python-only, for example. Start with the
[Python quickstart](./quickstart/python/) or
[TypeScript quickstart](./quickstart/typescript/), then check the language tabs
and provider pages for the feature you need.

## When should I use bidirectional streaming instead of standard streaming?

Standard [streaming](./streaming/async-iterators/) emits events as one agent
invocation produces its response. Both SDKs support async iteration, and Python
also supports callback handlers.

[Bidirectional agents](./bidi/) keep a live, full-duplex session open. They can
accept new text or audio while the model is still responding. Use them for
interruptible voice and other real-time interactions. The
[Bidi model adapters](./bidi/models/) list the current provider support.

## Should I build a custom tool or use an MCP tool?

Use a [custom tool](./tools/custom-tools/) for application code registered
directly with an agent. Use an [MCP tool](./tools/mcp-tools/) when the tool is
discovered and called through an MCP server. An agent can use both types
together.

When one model response requests several tools, both SDKs run them concurrently
by default. Choose a [sequential executor](./tools/executors/) when order matters
or the tools share mutable state that is not safe to access concurrently.

## Which multi-agent pattern fits my application?

The right pattern depends on who should control the execution path:

- Agents as tools keep one coordinator in control while it calls specialists.
- Agent-to-Agent (A2A) lets independently deployed agents communicate across
  service boundaries.
- A graph lets you define allowed nodes and edges, including branches and loops.
- In a swarm, agents choose which peer receives the next handoff.
- A workflow puts a fixed dependency graph in code for repeatable work.

The [multi-agent patterns](./multi-agent/multi-agent-patterns/) guide compares
examples and tradeoffs.

## How do sessions, memory, and context management work together?

[Session management](./agents/session-management/) persists conversation and
agent state so your application can resume work later.
[Long-term memory](./memory/overview/) stores selected knowledge for recall
across sessions without replaying the full conversation.
[Context management](./context-management) decides what stays in the active
model context as the conversation continues.

Applications often use sessions to restore state, memory to carry selected
knowledge across sessions, and context management to control the active model
window.

## Should I use automatic or agentic context management?

[Automatic mode](./context-management/built-in-modes/) uses SDK-defined
thresholds and actions to offload, truncate, or summarize context. A summary can
be model-written; the SDK still decides when the strategy runs.

Agentic mode gives the model context-usage information and tools so it can decide
when and what to compress or protect. It adds model work in exchange for more
judgment. The context manager strategy API, including agentic mode, is
experimental.

## What happens when structured output fails validation?

[Structured output](./agents/structured-output-behavior/) presents your schema
to the model as a tool. Strands validates the tool input and returns any errors
to the model so it can correct the result.

To set a firm bound, configure a failed structured-output attempt limit. If the
model reaches it, the invocation ends with a specific limit stop reason.

## When should I use hooks, plugins, middleware, or interventions?

- [Hooks](./agents/hooks/) respond to lifecycle events on an agent.
- [Plugins](./plugins/) package reusable behavior and attach it to agents.
- [Middleware](./agents/middleware/) wraps model or tool execution.
- [Interventions](./agents/interventions/) inspect an action and can allow,
  modify, reject, or pause it.

## How do I require approval for risky tool calls?

Use [Human in the Loop](./agents/approve-before-acting/) to pause selected tool
calls until a person approves or rejects them. Its optional model-based risk
classifier can reduce unnecessary prompts. The classifier is still a model
judgment, so it does not replace authorization.

If every call to a tool must prompt, use an explicit tool rule. If a permission
must never be overridable, enforce deterministic authorization such as a Cedar
policy before the approval step.

## When should I use retries or invocation limits?

Use [retry strategies](./agents/retry-strategies/) to recover individual model
calls from transient provider failures. Retry conditions, backoff, and defaults
differ between SDKs and providers, so configure them for your runtime.

Use [production lifecycle controls](./agents/lifecycle-controls/) to bound the
complete agent invocation. They cap turns, tokens, or failed structured-output
attempts, support cancellation, and return a stop reason that your application
can handle.

## Where can I deploy a Strands agent?

Strands agents run in your application process. Deploy it behind the entry point
required by the target environment. The
[deployment guides](./deploy/) cover serverless, container, Kubernetes, and
managed agent-runtime options.

Pick a target based on latency, streaming, state, network access, scaling, and
isolation requirements. Keeping environment details outside the agent lets the
same code move between targets.

## How do I observe a Strands agent in production?

The SDK emits
[OpenTelemetry traces and metrics](./observability-evaluation/observability/) and
works with your application's logging. Configure trace and metric exporters or a
collector, along with your logging handlers. Monitor model calls, tool calls,
latency, token use, errors, and application outcomes.

Telemetry can contain prompts, messages, and tool input or output. Handle it as
sensitive data: limit access and retention, collect only what you need, and
[redact personal data](./safety-security/pii-redaction/).

## Which security controls do I need in production?

No single SDK setting secures an agent. System prompts can steer behavior, but
they do not enforce policy. Give tools the least privilege they need, enforce
deterministic authorization, and add interventions, validation, guardrails,
trusted history, and telemetry controls. See
[Secure for production](./safety-security/).

In Python and TypeScript on Node.js, omitting the `sandbox` setting makes command
and file tools use the host process's permissions. Configure a
[Docker or SSH sandbox](./sandbox/), or a custom backend with the guarantees you
need. The sandbox interface routes operations, while the backend and its
environment determine the actual isolation boundary.
