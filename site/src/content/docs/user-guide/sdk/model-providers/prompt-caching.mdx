Your agent sends the same tools, system prompt, and earlier messages to the model on
every call. Prompt caching lets the model provider reuse that static part of the request
instead of processing it again. This page covers how Strands caches tools, system
prompts, and messages, and where caching falls short today.

Model providers handle the cache in one of two ways. Some let the request carry explicit
cache points. Others support only implicit caching and decide on their own what to
reuse. For pricing on cache writes and reads, see your model provider's documentation.

## Models that support explicit caching

To get the most savings from the cache, use a model that supports explicit cache points
and set the cache configuration strategy to `auto`. Strands then places the cache points
for you.

Strands puts the static content (tools, system prompt, and messages) before the cache
point. Ephemeral content, such as the text a
[context injector](../plugins/context-injector.md) adds for one model call, goes after
it. The injected text never enters the cache, and the static prefix still reads from it
on the next call.

## Models that support implicit caching

If your model supports only implicit caching, the model provider decides what to cache.
Strands can't put dynamic content after a cache point, because there isn't one. Content
that changes between calls changes the prefix the provider compares, so some of the
[harness's default settings](../../harness/configure/context-and-caching.md) break the
cache through normal use.

Gemini supports only implicit caching on its latest models. See
[Gemini context caching](https://aistudio.google.com/docs/caching). OpenAI models through
the Amazon Bedrock Converse API also support only implicit caching. Amazon Bedrock lists
which APIs take explicit cache points for each OpenAI model in
[Prompt caching for models from OpenAI](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html#prompt-caching-openai).

## Known gaps

In the following cases, caching silently does nothing or costs more than leaving it off.
Context injection and memory injected for a single call both come from content that
changes between calls, so the fix is the same: use a model with explicit caching, where
Strands keeps that content after the cache point.

### Context injection

A [context injector](../plugins/context-injector.md) and the
[context manager](../context-management.md) both add ephemeral content to the context
window before a model call. On a model with explicit caching, Strands keeps that content
out of the cached prefix. On a model with implicit caching, the injected content is
removed from history on the next call, so the next request no longer starts with the
previous one and the cache misses.

### Memory injection

Middleware that adds text to the latest message for a single call, which is how the
[memory manager](../memory/managing-memory.md) injects retrieved memories, breaks the
cache on a model with implicit caching. With explicit caching, Strands places the
injected text after the cache point, so it isn't cached and the
[context manager](../context-management.md) can change it on later turns.

### OpenAI models on the Converse API

The Converse API doesn't support cache points for OpenAI models. The provider caches
each request as a whole, and a later request reads that cache only if it starts with the
entire earlier request. Strands removes earlier injected content from the conversation
history before each call, so with a context injector or the harness defaults, no request
starts with the previous one. Every call is written to the cache and none is read. On
GPT-5.6 and later, cache writes cost 1.25 times the input rate, so this costs more than
not caching.

To cache these models on Amazon Bedrock, use the Responses API through
<Syntax py="OpenAIResponsesModel" ts="OpenAIModel" /> with Bedrock Mantle, and set a cache
configuration. To stop the extra cost on Converse instead, turn implicit caching off by
passing `prompt_cache_options` with `mode` set to `explicit` in the model's
<Syntax py="additional_request_fields" ts="additionalRequestFields" />.

### OpenAI Chat Completions

Strands places no cache points on the Chat Completions API, so it behaves like a model
provider with implicit caching, even for models that take cache points on other APIs.

### Background tasks

[Background tasks](../../harness/configure/background-tasks.md) add a label to each tool
that can run as a background task. The model receives an edited tool configuration,
which changes the bytes in the cached prefix and breaks the cache.

## Provider limits

Each model provider sets its own limits on caching, such as which models cache, the
minimum prompt size that is cached, the maximum number of cache points per request, and
how long a cache entry lasts. Strands doesn't change these limits. For the limits that
apply to your model, see the model provider's documentation:

- [Amazon Bedrock prompt caching](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)
- [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)
- [Gemini context caching](https://aistudio.google.com/docs/caching)
