An agent that serves several tenants (the customers of your application) often needs
three things from its models at once. It needs a small model for easy requests and a
stronger one for hard requests, a backup provider when a model fails, and a rule that
keeps each tenant on the models it has approved. This guide builds all three on one
[model router](./model-routing.md), with one tool set and one tracing configuration.

The examples use Amazon Nova Lite on [Amazon Bedrock](./amazon-bedrock.md) as the small
model, Claude Sonnet 5 on [Anthropic](./anthropic.md) as the strong model, and
[OpenAI](./openai.md) as the backup. A classifier on Amazon Bedrock picks between the
small and the strong model. Configure AWS credentials with Amazon Bedrock access and set
`ANTHROPIC_API_KEY` and `OPENAI_API_KEY` before running them.

## Describe each candidate for the policy

Give each candidate a description for the classifier and metadata for the tenant
policy. Here `provider` decides which tenants may use the candidate, and `tier` marks
the backup so the opening selection never picks it.

<Tabs>
<Tab label="Python">
```python
from strands.models import BedrockModel, RoutingCandidate
from strands.models.anthropic import AnthropicModel
from strands.models.openai import OpenAIModel

fast = BedrockModel(model_id="us.amazon.nova-lite-v1:0")
strong = AnthropicModel(model_id="claude-sonnet-5", max_tokens=1024)
backup = OpenAIModel(model_id="gpt-5.4")

candidates = [
    RoutingCandidate(
        fast,
        name="fast",
        description="Short factual questions and order lookups.",
        metadata={"provider": "bedrock", "tier": "primary"},
    ),
    RoutingCandidate(
        strong,
        name="strong",
        description="Multi-step reasoning, trade-offs, and recommendations.",
        metadata={"provider": "anthropic", "tier": "primary"},
    ),
    RoutingCandidate(
        backup,
        name="backup",
        description="Serves requests when the primary provider is unavailable.",
        metadata={"provider": "openai", "tier": "backup"},
    ),
]
```

Candidates must be stateless. The conversation stays in the agent, so a request that
fails over to another provider carries the earlier turns and tool calls with it.

## Enforce the tenant policy in the routing strategy

Put the policy in a custom routing strategy. The strategy reads the tenant from
invocation state and keeps only the candidates that tenant may use. On the first attempt
it asks a `ClassifierStrategy` to pick the allowed model that fits the request. After a
model failure it asks `FallbackStrategy` for the next allowed candidate, backup first, so
a hard request never drops to the small model. When no candidate qualifies, it raises an
error and logs the refusal.

<Tabs>
<Tab label="Python">
```python
import logging
from dataclasses import replace
from typing import Any

from strands.models import (
    ClassifierStrategy,
    FallbackStrategy,
    RoutingCandidate,
    RoutingContext,
)

audit_log = logging.getLogger("tenant_policy")

TENANT_PROVIDERS = {
    "customer-a": {"bedrock", "anthropic", "openai"},
    "customer-b": {"bedrock"},  # requests stay in Amazon Bedrock
}


class TenantPolicyError(Exception):
    """No candidate satisfies the tenant's model policy."""


class TenantPolicyStrategy:
    def __init__(self, classifier: ClassifierStrategy) -> None:
        self._classifier = classifier
        self._fallback = FallbackStrategy()

    async def select(
        self,
        context: RoutingContext,
        **kwargs: Any,
    ) -> RoutingCandidate | None:
        tenant = context.invocation_state.get("tenant")
        providers = TENANT_PROVIDERS.get(tenant, set())
        allowed = [
            c for c in context.candidates
            if (c.metadata or {}).get("provider") in providers
        ]
        if not allowed:
            audit_log.warning("tenant=<%s> | no allowed model, refusing call", tenant)
            raise TenantPolicyError(f"tenant {tenant!r} has no allowed model")

        if context.attempts:
            # Fail over to the backup first, so a hard request never drops to the
            # small model
            backups = [c for c in allowed if c.metadata["tier"] == "backup"]
            others = [c for c in allowed if c not in backups]
            scoped = replace(context, candidates=backups + others)
            choice = await self._fallback.select(scoped, **kwargs)
        else:
            primaries = [
                c for c in allowed if c.metadata["tier"] == "primary"
            ] or allowed
            scoped = replace(context, candidates=primaries)
            # A declined classification would serve the router's first candidate,
            # which this tenant may not be allowed to use
            choice = await self._classifier.select(scoped, **kwargs) or primaries[0]
        audit_log.info(
            "tenant=<%s>, candidate=<%s>, attempt=<%s> | routing decision",
            tenant,
            choice.name if choice else None,
            "retry" if context.attempts else "first",
        )
        return choice
```

A `BeforeModelCallEvent` hook looks like the natural place for this check. But the
router picks the model after that hook runs, so the hook cannot see which candidate
will serve the call. The same holds for a `before_model_call` intervention, which runs
on that event. The strategy sees the candidates, and the policy then also applies on
failover: `customer-b` never falls back to Anthropic or OpenAI, even when Amazon Bedrock
fails.

The classifier reads every request, so run it on a model that every tenant allows. Here
that is Claude Haiku on Amazon Bedrock. With one allowed model, such as for `customer-b`,
`ClassifierStrategy` returns it without a classification call.

## Run the agent for a tenant

Attach the router as the agent's model and pass the tenant with each request. This
example reuses `candidates` and `TenantPolicyStrategy` from the previous sections and
shows each routing decision in the log.

<Tabs>
<Tab label="Python">
```python
import logging

from strands import Agent, tool
from strands.models import BedrockModel, ClassifierStrategy, ModelRouter

logging.basicConfig(format="%(message)s")
logging.getLogger("tenant_policy").setLevel(logging.INFO)


@tool
def lookup_order(order_id: str) -> dict:
    """Look up the shipping status of an order, such as A-1001."""
    orders = {"A-1001": {"status": "shipped", "eta": "Nov 6"}}
    return orders.get(order_id, {"status": "not found"})


classifier = ClassifierStrategy(
    BedrockModel(
        model_id="us.anthropic.claude-haiku-4-5-20251001-v1:0",
        max_tokens=64,
        streaming=False,
        temperature=0,
    )
)
router = ModelRouter(models=candidates, strategy=TenantPolicyStrategy(classifier))
agent = Agent(model=router, tools=[lookup_order])

agent("Where is order A-1001?", invocation_state={"tenant": "customer-a"})
```

The policy log shows:

```text
tenant=<customer-a>, candidate=<fast>, attempt=<first> | routing decision
```

A tenant with no policy, such as `unknown-customer`, gets `TenantPolicyError` before any
model runs, and the log records the refusal:

```text
tenant=<unknown-customer> | no allowed model, refusing call
```

A model fails when its call raises an error instead of returning a response: the
provider is down or times out, the account is throttled after the agent's retries, or
the credentials or model access are invalid. The router reacts only to these errors, not
to the content of a response.

When a model fails, the router asks the strategy again with the failed attempt. If Claude
Sonnet 5 fails on a hard request, `customer-a` moves to the OpenAI backup, not to Nova
Lite. If Nova Lite fails, `customer-b` has no candidate left, so the original model error
reaches the caller.

Example:

```text
tenant=<customer-a>, candidate=<strong>, attempt=<first> | routing decision
tenant=<customer-a>, candidate=<backup>, attempt=<retry> | routing decision
tenant=<customer-b>, candidate=<fast>, attempt=<first> | routing decision
tenant=<customer-b>, candidate=<None>, attempt=<retry> | routing decision
```
