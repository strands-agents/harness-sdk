Amazon Bedrock AgentCore Runtime is a serverless hosting environment for agents and tools.
It runs agents built with any framework, including Strands Agents, on any model provider,
and serves them over HTTP, MCP, A2A, or AG-UI. Each user session runs in its own microVM
with isolated CPU, memory, and filesystem, sessions can run for up to eight hours, and you
pay for the resources your agent consumes rather than for provisioned capacity. Through
AgentCore Identity, users sign in with providers such as Amazon Cognito, Microsoft Entra
ID, and Okta, and your agent reaches services such as GitHub and Slack with OAuth or API
keys.

## How deployment works

These guides deploy with the [AgentCore CLI](https://github.com/aws/agentcore-cli), the
same in Python and TypeScript. A project declares your runtimes and the AgentCore
resources they use, such as AgentCore Memory, in `agentcore/agentcore.json`. From there:

- `agentcore create` scaffolds a project from a Strands template, and
  `agentcore add runtime` registers agent code you already have.
- `agentcore dev` runs the agent locally with hot reload.
- `agentcore deploy` packages your code as a zip, provisions the runtime, its IAM role,
  and the other resources with AWS CDK, and enables CloudWatch Transaction Search for
  traces. Add a `Dockerfile` to build a container in AWS CodeBuild instead.
- `agentcore invoke`, `agentcore logs`, and `agentcore traces` talk to the deployed agent
  and show what it did.

You don't need Docker, a container registry, or hand-written IAM policies.

## Prerequisites

- An AWS account with credentials configured, and
  [permissions for AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-permissions.html)
- Node.js 20.12 or later for the AgentCore CLI (Node.js 22 or later for TypeScript agents)
- For Python agents: Python 3.10 or later and
  [uv](https://docs.astral.sh/uv/getting-started/installation/)
