This guide deploys a TypeScript Strands agent to
[Amazon Bedrock AgentCore Runtime](index.md) with the
[AgentCore CLI](https://github.com/aws/agentcore-cli). The CLI scaffolds the project, runs
the agent locally, bundles your code, and provisions the runtime, its IAM role, and an
AgentCore Memory resource through AWS CDK. You don't need Docker or a container registry.

## Prerequisites

- An AWS account with credentials configured, and
  [permissions for AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-permissions.html)
- Node.js 22 or later, for the AgentCore CLI and your agent

## Install the AgentCore CLI

```bash
npm install -g @aws/agentcore
agentcore --version
```

If `agentcore --version` fails or the CLI offers commands such as `configure` and
`launch`, the older Bedrock AgentCore Starter Toolkit is shadowing it. Run
`pip uninstall bedrock-agentcore-starter-toolkit` and open a new terminal.

## Create a project

The CLI deploys to the region in `AWS_REGION` (or your AWS profile's region), and records
it on the first deploy. Set it, then create a project from the Strands template:

```bash
export AWS_REGION=us-east-1
agentcore create --name MyAgent --template agent-typescript-strands
cd MyAgent
```

The template creates a runtime named `agent`, adds an AgentCore Memory resource, installs
the dependencies with `npm install`, and initializes a Git repository:

```
MyAgent/
├── agentcore/
│   ├── agentcore.json      # Project spec
│   ├── aws-targets.json    # Deployment account and region
│   ├── .env.local          # Local-only variables (gitignored)
│   └── cdk/                # CDK app that deploys the project
└── app/
    └── agent/
        ├── main.ts         # Runtime entrypoint and Strands agent
        ├── model/load.ts   # Model configuration
        ├── memory/memory.ts
        └── package.json    # Dependencies
```

The template's dependency ranges can trail the latest Strands SDK. Update the Strands SDK
and `bedrock-agentcore` to their latest releases, together with `zod`, which the Strands
SDK requires:

```bash
cd app/agent
npm install @strands-agents/sdk@latest bedrock-agentcore@latest zod@latest
cd ../..
```

The template uses Amazon Bedrock. To use Anthropic, OpenAI, Gemini, or an
OpenAI-compatible endpoint, run `agentcore create` with no flags and choose the provider
in the wizard. The CLI keeps the API key in `agentcore/.env.local` and provisions it as an
AgentCore Identity credential when you deploy.

## Understand the agent code

`app/agent/main.ts` wraps a Strands agent in a `BedrockAgentCoreApp` from the
[`bedrock-agentcore`](https://github.com/aws/bedrock-agentcore-sdk-typescript) package.
The app serves the
[HTTP contract](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-http-protocol-contract.html)
AgentCore Runtime expects: `POST /invocations` and `GET /ping` on port 8080. This excerpt
shows the invocation handler:

```typescript
const app = new BedrockAgentCoreApp({
  invocationHandler: {
    requestSchema,
    async *process(payload, context) {
      const sessionId = context?.sessionId ?? 'default-session'
      const agent = await getOrCreateAgent(sessionId, payload.actorId)

      try {
        for await (const event of agent.stream(payload.prompt)) {
          // Yields each text delta from the model's response
        }
      } finally {
        await agent.memoryManager?.flush()
      }
    },
  },
})
```

The handler validates `prompt` and an optional `actorId` (the end user) from the JSON
payload with a Zod schema, gets one agent per session and user, and streams the text of
the response back as server-sent events. Add tools to the `tools` list in the same file,
and change the model in `model/load.ts`.

## Run the agent locally

```bash
agentcore dev
```

`agentcore dev` serves the agent on port 8080 with hot reload, using your local AWS
credentials. Add `--mode browser` to chat with it in the Agent Inspector, or `--port` if
8080 is taken. In another terminal, send it a prompt:

```bash
agentcore invoke --runtime agent --local --payload '{"prompt": "What is 21 + 21?"}'
```

The response streams back as server-sent events, one text chunk per line:

```
data: "21 + 21 ="

data: " 42."
```

## Deploy to AgentCore Runtime

```bash
agentcore deploy
```

The first deploy takes a few minutes. The CLI records the deployment target in
`agentcore/aws-targets.json`, bootstraps CDK in the region if needed, enables CloudWatch
Transaction Search for traces, and deploys a CloudFormation stack named
`AgentCore-MyAgent-default` with the runtime, its execution role, and the memory. It
bundles `main.ts` and everything it imports from your local `node_modules` into one
`main.js` with esbuild and uploads it as a zip (a CodeZip build), so you don't need a
build step. If a deploy fails, run `agentcore deploy --debug` for the full output.

Check what is deployed:

```bash
agentcore status
```

`agentcore status --json` includes each resource's ARN, which you need to invoke the agent
from your own code.

## Invoke the deployed agent

### From the CLI

```bash
agentcore invoke --runtime agent --payload '{"prompt": "Hello, what can you do?"}'
```

Each invocation runs in a session, and each session gets its own microVM. Pass the same
`--session-id` (33 to 100 characters) to continue a conversation.

### From your application

Call `InvokeAgentRuntime` with the AWS SDK for JavaScript
(`npm install @aws-sdk/client-bedrock-agentcore`). The runtime ARN comes from
`agentcore status --json`, and the payload and response match the local run above. Set
`contentType` and `accept`: the runtime rejects requests without them.

```typescript
import { randomUUID } from 'node:crypto'
import {
  BedrockAgentCoreClient,
  InvokeAgentRuntimeCommand,
} from '@aws-sdk/client-bedrock-agentcore'

const AGENT_ARN =
  'arn:aws:bedrock-agentcore:us-east-1:123456789012:' +
  'runtime/MyAgent_default_agent-a1b2c3d4e5'

const client = new BedrockAgentCoreClient({ region: 'us-east-1' })

const response = await client.send(
  new InvokeAgentRuntimeCommand({
    agentRuntimeArn: AGENT_ARN,
    runtimeSessionId: randomUUID(),
    contentType: 'application/json',
    accept: 'text/event-stream',
    payload: JSON.stringify({ prompt: 'What is 40 + 2?', actorId: 'user-1' }),
  })
)

const decoder = new TextDecoder()
let buffer = ''
for await (const chunk of response.response!) {
  buffer += decoder.decode(chunk, { stream: true })
  const lines = buffer.split('\n')
  buffer = lines.pop() ?? ''
  for (const line of lines) {
    if (line.startsWith('data: ')) process.stdout.write(JSON.parse(line.slice(6)))
  }
}
process.stdout.write('\n')
```

Reuse `runtimeSessionId` across calls to keep a conversation in the same session.

## Deploy your own agent code

To deploy an agent you already have, register a runtime for it instead of starting from
the template. Run this in a project (create one with `agentcore create --name MyProject`
if you don't have one):

```bash
agentcore add runtime --name myagent --language typescript
```

`add runtime` doesn't generate code. It registers the runtime in `agentcore.json` and
writes `app/myagent/README.md` and `AGENTS.md`, which describe what the code must provide.
Add an entrypoint at `app/myagent/main.ts`:

```typescript
import { Agent } from '@strands-agents/sdk'
import { BedrockAgentCoreApp } from 'bedrock-agentcore/runtime'
import { z } from 'zod'

const agent = new Agent()

const app = new BedrockAgentCoreApp({
  invocationHandler: {
    requestSchema: z.object({ prompt: z.string() }),
    async *process(payload) {
      for await (const event of agent.stream(payload.prompt)) {
        if (
          event.type === 'modelStreamUpdateEvent' &&
          event.event.type === 'modelContentBlockDeltaEvent' &&
          event.event.delta.type === 'textDelta'
        ) {
          yield { data: event.event.delta.text }
        }
      }
    },
  },
})

app.run({ port: Number(process.env.PORT ?? 8080) })
```

Read the port from `PORT` so `agentcore dev` can move it. Each session has its own
microVM, so a module-level agent keeps one conversation per session once deployed. The CLI
bundles the code as CommonJS, so don't use top-level `await` in `main.ts` or anything it
imports; do async setup inside the handler instead.

Add `app/myagent/package.json` and install the dependencies. The CLI bundles from
`node_modules`, so install them before you deploy, and `agentcore dev` runs `main.ts` with
`tsx`:

```json
{
  "name": "myagent",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "main": "main.ts",
  "engines": {
    "node": ">=22"
  }
}
```

```bash
cd app/myagent
npm install @strands-agents/sdk bedrock-agentcore zod
npm install -D tsx
cd ../..
```

Run, deploy, and invoke it like the template agent:

```bash
agentcore dev --agent myagent
agentcore deploy
agentcore invoke --runtime myagent --payload '{"prompt": "Hello"}'
```

If you need system packages or full control of the image, add a `Dockerfile` to
`app/myagent/`. The CLI switches the runtime to a container build, which it builds in AWS
CodeBuild, so you still don't need Docker to deploy. The generated `README.md` has a
starting Dockerfile.

## Use AgentCore Memory

The template's agent stores each conversation in the AgentCore Memory resource named
`agentMemory`, and recalls facts, preferences, and summaries about the same `actorId` in
later sessions. The CLI passes the memory ID to the runtime as `MEMORY_AGENTMEMORY_ID`,
and `memory/memory.ts` builds a Strands `MemoryManager` from it. For example, tell the
agent something in one session and ask about it in another:

```bash
agentcore invoke --runtime agent --session-id "$(uuidgen)-session-one" \
  --payload '{"prompt": "My favourite colour is teal.", "actorId": "sam"}'
agentcore invoke --runtime agent --session-id "$(uuidgen)-session-two" \
  --payload '{"prompt": "What is my favourite colour?", "actorId": "sam"}'
```

Long-term memory is extracted in the background, so a fact can take a few minutes to
appear in a new session. If you don't need memory, remove it and deploy; the agent skips
memory when `MEMORY_AGENTMEMORY_ID` isn't set:

```bash
agentcore remove memory --name agentMemory
agentcore deploy
```

See [AgentCore Memory](../../../../integrations/memory-stores/agentcore-memory-store.md)
for the memory store's options.

## Observe your agent

The deployed runtime sends its logs to CloudWatch. Search or tail them (pass `--name` when
the project has more than one runtime). The server writes JSON log lines with numeric
levels, so filter them with a CloudWatch filter pattern; 50 and above are errors:

```bash
agentcore logs runtime --since 30m --query '{ $.level >= 50 }'
agentcore logs runtime --tail
```

The CLI doesn't add OpenTelemetry instrumentation to TypeScript runtimes, so they send no
traces and `agentcore traces` finds none for them. To send traces, instrument the agent
with the AWS Distro for OpenTelemetry for Node.js, as described in
[Direct code deployment for Node.js](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy-node.html).
See
[AgentCore observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html)
for the metrics and spans AgentCore records.

## Clean up

Remove every resource from the project, then deploy the empty project to delete its stack:

```bash
agentcore remove all --yes
agentcore deploy --yes
```

The runtimes' CloudWatch log groups, named
`/aws/bedrock-agentcore/runtimes/<runtime-id>-DEFAULT`, stay until you delete them.
