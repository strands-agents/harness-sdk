This guide deploys a Python Strands agent to [Amazon Bedrock AgentCore Runtime](index.md)
with the [AgentCore CLI](https://github.com/aws/agentcore-cli). The CLI scaffolds the
project, runs the agent locally, packages your code, and provisions the runtime, its IAM
role, and an AgentCore Memory resource through AWS CDK. You don't need Docker or a
container registry.

## Prerequisites

- An AWS account with credentials configured, and
  [permissions for AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-permissions.html)
- Node.js 20.12 or later, for the AgentCore CLI
- Python 3.10 or later
- [uv](https://docs.astral.sh/uv/getting-started/installation/), which the CLI uses to
  install and run your agent's dependencies

## Install the AgentCore CLI

```bash
npm install -g @aws/agentcore
agentcore --version
```

If `agentcore --version` fails or the CLI offers commands such as `configure` and
`launch`, the older Bedrock AgentCore Starter Toolkit is shadowing it. Run
`pip uninstall bedrock-agentcore-starter-toolkit` and open a new terminal.

## Create a project

The CLI deploys to the region in `AWS_REGION` (or your AWS profile's region), and records
it on the first deploy. Set it, then create a project from the Strands template:

```bash
export AWS_REGION=us-east-1
agentcore create --name MyAgent --template agent-python-strands
cd MyAgent
```

The template creates a runtime named `agent`, adds an AgentCore Memory resource, installs
the dependencies with `uv sync`, and initializes a Git repository:

```
MyAgent/
├── agentcore/
│   ├── agentcore.json      # Project spec
│   ├── aws-targets.json    # Deployment account and region
│   ├── .env.local          # Local-only variables (gitignored)
│   └── cdk/                # CDK app that deploys the project
└── app/
    └── agent/
        ├── main.py         # Runtime entrypoint and Strands agent
        ├── model/load.py   # Model configuration
        ├── memory/session.py
        └── pyproject.toml  # Dependencies
```

The template uses Amazon Bedrock. To use Anthropic, OpenAI, Gemini, LiteLLM, or an
OpenAI-compatible endpoint, run `agentcore create` with no flags and choose the provider
in the wizard. The CLI keeps the API key in `agentcore/.env.local` and provisions it as an
AgentCore Identity credential when you deploy.

## Understand the agent code

`app/agent/main.py` wraps a Strands agent in a `BedrockAgentCoreApp` from the
[`bedrock-agentcore`](https://github.com/aws/bedrock-agentcore-sdk-python) package. The
app serves the
[HTTP contract](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-http-protocol-contract.html)
AgentCore Runtime expects: `POST /invocations` and `GET /ping` on port 8080. This excerpt
shows the entrypoint:

```python
@app.entrypoint
async def invoke(payload, context):
    session_id = getattr(context, "session_id", None) or "default-session"
    prompt, actor_id = parse_payload(payload)
    agent = _get_agent(session_id, actor_id)

    async for event in agent.stream_async(prompt):
        ...
        yield event
```

The entrypoint reads `prompt` and an optional `actorId` (the end user) from the JSON
payload, gets one agent per session and user, and streams the agent's model events back as
server-sent events. Add tools to the `tools` list in the same file, and change the model
in `model/load.py`.

## Run the agent locally

```bash
agentcore dev
```

`agentcore dev` serves the agent on port 8080 with hot reload, using your local AWS
credentials. Add `--mode browser` to chat with it in the Agent Inspector, or `--port` if
8080 is taken. In another terminal, send it a prompt:

```bash
agentcore invoke --runtime agent --local --payload '{"prompt": "What is 21 + 21?"}'
```

The response streams back as server-sent events, one Strands model event per line:

```
data: {"event": {"contentBlockDelta": {"delta": {"text": "21 + 21 ="}, ...}}}

data: {"event": {"contentBlockDelta": {"delta": {"text": " 42."}, ...}}}
```

## Deploy to AgentCore Runtime

```bash
agentcore deploy
```

The first deploy takes a few minutes. The CLI records the deployment target in
`agentcore/aws-targets.json`, bootstraps CDK in the region if needed, enables CloudWatch
Transaction Search for traces, and deploys a CloudFormation stack named
`AgentCore-MyAgent-default` with the runtime, its execution role, and the memory. It
installs your dependencies as ARM64 Linux wheels and uploads them with your code as a zip
(a CodeZip build). If a deploy fails, run `agentcore deploy --debug` for the full output.

Check what is deployed:

```bash
agentcore status
```

`agentcore status --json` includes each resource's ARN, which you need to invoke the agent
from your own code.

## Invoke the deployed agent

### From the CLI

```bash
agentcore invoke --runtime agent --payload '{"prompt": "Hello, what can you do?"}'
```

Each invocation runs in a session, and each session gets its own microVM. Pass the same
`--session-id` (33 to 100 characters) to continue a conversation.

### From your application

Call `InvokeAgentRuntime` with boto3. The runtime ARN comes from
`agentcore status --json`, and the payload and response match the local run above:

```python
import json
import uuid

import boto3

AGENT_ARN = (
    "arn:aws:bedrock-agentcore:us-east-1:123456789012:"
    "runtime/MyAgent_default_agent-a1b2c3d4e5"
)

client = boto3.client("bedrock-agentcore", region_name="us-east-1")

response = client.invoke_agent_runtime(
    agentRuntimeArn=AGENT_ARN,
    runtimeSessionId=str(uuid.uuid4()),
    contentType="application/json",
    accept="text/event-stream",
    payload=json.dumps({"prompt": "What is 40 + 2?", "actorId": "user-1"}),
)

for line in response["response"].iter_lines():
    if not line.startswith(b"data: "):
        continue
    event = json.loads(line[len(b"data: "):])
    delta = event.get("event", {}).get("contentBlockDelta", {}).get("delta", {})
    if "text" in delta:
        print(delta["text"], end="", flush=True)
print()
```

Reuse `runtimeSessionId` across calls to keep a conversation in the same session.

## Deploy your own agent code

To deploy an agent you already have, register a runtime for it instead of starting from
the template. Run this in a project (create one with `agentcore create --name MyProject`
if you don't have one):

```bash
agentcore add runtime --name myagent --language python
```

`add runtime` doesn't generate code. It registers the runtime in `agentcore.json` and
writes `app/myagent/README.md` and `AGENTS.md`, which describe what the code must provide.
Add an entrypoint at `app/myagent/main.py`:

```python
from bedrock_agentcore.runtime import BedrockAgentCoreApp
from strands import Agent

app = BedrockAgentCoreApp()
agent = Agent()


@app.entrypoint
async def invoke(payload, context):
    async for event in agent.stream_async(payload.get("prompt", "")):
        if "data" in event:
            yield event["data"]


if __name__ == "__main__":
    app.run()
```

This version streams only the text of the response. Keep the module-level `app` and the
`app.run()` call: `agentcore dev` serves the `app` object, and the deployed runtime runs
`main.py` directly. Each session has its own microVM, so a module-level agent keeps one
conversation per session once deployed.

Declare the dependencies in `app/myagent/pyproject.toml`. The CLI reads only
`[project].dependencies`, and AgentCore starts Python code with
`opentelemetry-instrument`, so `aws-opentelemetry-distro` is required:

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "myagent"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = [
    "aws-opentelemetry-distro",
    "bedrock-agentcore",
    "strands-agents",
]

[tool.hatch.build.targets.wheel]
packages = ["."]
```

Run, deploy, and invoke it like the template agent:

```bash
agentcore dev --agent myagent
agentcore deploy
agentcore invoke --runtime myagent --payload '{"prompt": "Hello"}'
```

If you need system packages or a dependency that has no ARM64 Linux wheel, add a
`Dockerfile` to `app/myagent/`. The CLI switches the runtime to a container build, which
it builds in AWS CodeBuild, so you still don't need Docker to deploy. The generated
`README.md` has a starting Dockerfile.

## Use AgentCore Memory

The template's agent stores each conversation in the AgentCore Memory resource named
`agentMemory`, and recalls facts, preferences, and summaries about the same `actorId` in
later sessions. The CLI passes the memory ID to the runtime as `MEMORY_AGENTMEMORY_ID`,
and `memory/session.py` sets up a Strands session manager from it. For example, tell the
agent something in one session and ask about it in another:

```bash
agentcore invoke --runtime agent --session-id "$(uuidgen)-session-one" \
  --payload '{"prompt": "My favourite colour is teal.", "actorId": "sam"}'
agentcore invoke --runtime agent --session-id "$(uuidgen)-session-two" \
  --payload '{"prompt": "What is my favourite colour?", "actorId": "sam"}'
```

Long-term memory is extracted in the background, so a fact can take a few minutes to
appear in a new session. If you don't need memory, remove it and deploy; the agent skips
memory when `MEMORY_AGENTMEMORY_ID` isn't set:

```bash
agentcore remove memory --name agentMemory
agentcore deploy
```

See [AgentCore Memory](../../../../integrations/session-managers/agentcore-memory.md) for
the session manager's options.

## Observe your agent

The deployed runtime sends logs and traces to CloudWatch without extra setup:
`aws-opentelemetry-distro` instruments the agent, and `agentcore deploy` enables
Transaction Search the first time. To keep the CLI from enabling Transaction Search, run
`agentcore config transactionSearch false`.

Search or tail the runtime's logs (pass `--name` when the project has more than one
runtime):

```bash
agentcore logs runtime --since 30m --level error
agentcore logs runtime --tail
```

Traces appear two to three minutes after an invocation. List them, then download one:

```bash
agentcore traces runtime list --since 30m
agentcore traces runtime get <trace-id>
```

For dashboards across sessions, open the **GenAI Observability** page in the CloudWatch
console. To connect an invocation to a trace from your own system, pass trace context when
you invoke: `--trace-parent`, `--trace-id`, and `--baggage` on `agentcore invoke`, or
`traceParent`, `traceId`, and `baggage` on `invoke_agent_runtime`. See
[AgentCore observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html)
for the metrics and spans AgentCore records.

## Clean up

Remove every resource from the project, then deploy the empty project to delete its stack:

```bash
agentcore remove all --yes
agentcore deploy --yes
```

The runtimes' CloudWatch log groups, named
`/aws/bedrock-agentcore/runtimes/<runtime-id>-DEFAULT`, stay until you delete them.
