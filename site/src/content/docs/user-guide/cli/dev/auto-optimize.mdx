When you chat with an agent in `strands dev` every day, your chats are a good source of test cases. Auto-optimize uses them.
Every N chat turns, dev makes an experiment from your chats and optimizes the agent on it, in the background. You do not type a command.

Two settings control this, in the **Strands dev workspace** section of `/settings`:

- **Auto-optimize every N turns** starts the work.
- **Auto-accept optimization results** applies the edits of a finished run without a review.

The two settings are off by default. Dev saves them in the workspace, so they apply only to this agent. They work for the [Base CLI](/docs/user-guide/cli/dev/base-cli/) and for a [harness in code](/docs/user-guide/cli/dev/harness/).

## Turn on auto-optimize

1. Type `/settings`, and open the **Strands dev workspace** section.
2. In **Auto-optimize every N turns**, select 5, 10, 20, 50, or 100.

You can also ask the agent, for example "optimize every 20 turns from my history".

Each automatic run makes paid model calls, for the agent that makes the experiment and for the optimization.

## What counts as a chat turn

A chat turn is a message that you send and that the agent answers. A command such as `/model`, a shell command that starts with `!`, and a skill that starts with `$` do not count.
The count starts after the turn that sets the number, and a new number starts the count again. Dev keeps the count when it closes.

## What happens when a run is due

1. A notice in the chat says that the work started, and the line below the chat input shows it.
2. An agent in a process of its own makes an experiment from your chats with this agent. That process has no session, and it asks you nothing. The experiment gets a name such as `history-20261124-1530`, and it must have 3 cases or more.
3. Dev starts an optimization on that experiment with the default settings of the plan.
4. The notice tells you the name of the experiment and the number of its cases. Or it tells you why no optimization started.

The process writes its log to `strands-dev/tmp/.state/auto-optimize/<experiment>.log`.

## When a run waits or stops

A run that is due waits while another optimization runs, or while the edits of a finished optimization wait for your answer.
The work stops when you turn the setting off or close dev. Then the run is due again at your next chat turn.

## How you get the result

When the optimization finishes, its edits show on screen as a diff, one edit at a time, as for `/optimize`. Select **Apply this change** or **Leave it as it is**.
[How optimization works](/docs/user-guide/cli/dev/optimization/) explains how the optimizer picks the edits that it recommends.

## Apply the edits without a review

When **Auto-accept optimization results** is on, a run that finishes writes its edits into the agent without a diff. Then dev tells you what it applied.
Two kinds of edits still wait for your review:

- The edits of a run that you stop early.
- A review that already waited when you turned on the setting.

With the two settings on, the agent changes without your review. Keep auto-accept off until you trust the experiments that dev makes from your chats.
