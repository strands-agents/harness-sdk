The Base CLI is the agent that `strands` runs. In this guide, you open the Base CLI in `strands dev`, you test it on an experiment, and you apply the edits of the optimizer.
The edits go into your saved profile. The next `strands` that you start uses them.

## Before you start

Make sure that you have the items in [What you need](/docs/user-guide/cli/dev/#what-you-need).
It is not necessary to run plain `strands` first. When you have no saved profile, the Base CLI is the default profile, and dev saves your first change in `~/.strands/cli.toml`.

## Open the Base CLI in dev

Run `strands dev`. Under **Global Harness**, select **Base CLI**. The row shows the path of your `cli.toml`.

Dev uses the workspace `~/.strands/strands-dev/`. When that folder does not have the workspace yet, dev asks for a folder, and the field starts with `~/.strands`. Push Enter.
To prepare the workspace from a shell without a chat, run `strands dev init --create cli`.

## Where your changes go

When the Base CLI is your saved profile, dev writes each change into the profile in `~/.strands/cli.toml`:

- The model and the effort that you select with `/model` and `/effort`.
- The edits that you apply from `/optimize`.
- The appearance settings: the theme, the transcript spacing, the animations, the reasoning, and the tool output. Thus dev and plain `strands` look the same.

Dev shows the profile as an agent file in `~/.strands/strands-dev/agent/`. That file is only a view of the profile, and dev writes it again at each start. Do not edit it.
When you edit `cli.toml`, dev reloads the agent. Plain `strands` reads the changed profile the next time that it starts.

When `cli.toml` names an agent file in `agentProject`, the Base CLI is that file. Then dev writes the changes into the file, as for [a harness in code](/docs/user-guide/cli/dev/harness/).

## Make an experiment

Type `/experiment`. The agent asks what the experiment must test. Write the topic of the cases. Or write "past chats" to make the cases from your earlier dev chats with this agent.
The agent gives a name and a number of cases, and it waits for your approval. Reply "yes".

The generation runs in the background, and a line below the chat input shows its progress. When it finishes, a notice gives the path of the experiment file.

## Run the experiment

Type `/experiment`, select the experiment, and select **Run it**. The selection is your approval, and the run starts at once.
When the run finishes, select **View its last report** from `/experiment`. The agent gives the passed cases, the total, and the score, and the reason for each failure.

## Optimize the Base CLI

Type `/optimize`. The agent asks which experiment to use, which options to tune, what the run must improve, what must stay true, and the budget.
Then it prints a review of the run. Reply "approve" to start the run, or name a row to change it.

A profile can hold only some options. For the Base CLI, the optimizer can tune these options:

- The model, the effort, and the instructions.
- Prompt caching and the context manager.
- The built-in tools, the built-in plugins, and the MCP servers.

The other options show as not available.

When the run finishes, the proposed edits show on screen as a diff, one edit at a time. Select **Apply this change** or **Leave it as it is**.
When each edit has an answer, dev writes the edits that you applied into `cli.toml`, and then dev reloads the agent.

## Use the result in plain strands

Type `/exit` to close dev, and run `strands`. The chat uses the updated profile.
To measure the change again, open the Base CLI in `strands dev`, and run the experiment again from `/experiment`.
