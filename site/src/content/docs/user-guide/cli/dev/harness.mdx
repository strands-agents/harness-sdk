In this guide, you open a harness project in `strands dev`. You chat with the agent while you change its code.
Then you test the agent on an experiment, and you apply the edits of the optimizer to its source file.

## Before you start

- Get a harness project, or an empty folder for a new project.
- For a Python harness, install Python 3.10 or later. When `python3` on your path is older, set `PYTHON` to a newer interpreter.
- Make sure that you have the items in [What you need](/docs/user-guide/cli/dev/#what-you-need).

## Open your harness

Run `strands dev` in the folder of your project. The picker shows your harness files under **Discovered Harnesses**. Select one.

Dev shows a file only when it can load the agent of the file:

- In TypeScript, a top-level `agent` comes from one `createHarness(...)` call, or from a call to a local function.
- In Python, `agent` comes from `create_harness(...)`. Or the file defines `create_agent` and sets `agent` from a local function.

To start without the picker, give the file: `strands dev --agent ./agent.py`.

Dev makes the workspace `strands-dev/` in the folder of the agent file. Then dev prepares the project: npm installs the dependencies of a TypeScript project, and a Python project gets a `.venv`.

### Make a new harness

To start from nothing, select **Create a new harness** under **New Harness**. Type a name. The language is Python. To select TypeScript, push Tab. Then push Enter.
Dev makes the project in `strands-workspace/` in the current folder:

```text
strands-workspace/
  agent.py        the harness agent
  strands-dev/    the workspace of strands dev
```

The new harness is a general-purpose agent with the model settings of your saved profile.

## Change the agent while you chat

Ask the agent a question. Then change its source, for example the instructions of the `create_harness` call:

```python
from strands_harness import create_harness

agent = create_harness(
    name="support-agent",
    instructions="You answer questions about the refund policy of an online store. Answer in two sentences or less.",
)
```

Save the file. Dev reloads the agent, keeps the conversation, and shows `↻ agent.py reloaded · session kept` in the status line.
Dev reloads for changes to code, instruction text, configuration files, Cedar policies, skill files, MCP configuration, and dependency manifests. A log or a data file does not cause a reload.

When you change the model or the effort with `/model` and `/effort`, dev writes the change into the `create_harness` or `createHarness` call. When the call sets that option from a variable, dev does not change the file. Then the change applies to the current chat only.

## Make an experiment

Type `/experiment`. The agent asks what the experiment must test. Write the topic of the cases, for example "questions about refunds, late fees, and damaged items". You can also write "past chats" to make the cases from your earlier dev chats with this agent.
The agent gives a name and a number of cases, and it waits for your approval. Reply "yes".

The generation runs in the background, and a line below the chat input shows its progress. When it finishes, a notice gives the path of the experiment file, `strands-dev/experiments/<name>/<name>.json`.

## Run the experiment

Type `/experiment`, select the experiment, and select **Run it**. The selection is your approval, and the run starts at once.
When the run finishes, select **View its last report** from `/experiment`. The agent gives the passed cases, the total, and the score, and the reason for each failure.

From a shell, `strands dev evaluate <experiment>` runs the same evaluation and prints the result.

## Optimize the harness

Type `/optimize`. The agent asks which experiment to use, which options to tune, what the run must improve, what must stay true, and the budget. For a first run, select a small budget.
Then it prints a review of the run, with the estimated rollouts and judge calls. Reply "approve" to start the run, or name a row to change it.

The options to tune are the arguments of the `create_harness` or `createHarness` call: the instructions, the model, the effort, and more. An option that the call leaves out starts from the default of the harness. When you apply its edit, dev writes the option into the call.

When the run finishes, the proposed edits show on screen as a diff, one edit at a time. Select **Apply this change** or **Leave it as it is**.
When each edit has an answer, dev writes the edits that you applied into the agent file. Then dev reloads the agent.

[How optimization works](/docs/user-guide/cli/dev/optimization/) explains how the optimizer picks the edits that it recommends. To optimize from your chats without a command, see [Optimize automatically](/docs/user-guide/cli/dev/auto-optimize/).

## Keep the results

The workspace keeps each experiment and its history in one folder:

```text
strands-dev/experiments/<name>/
  <name>.json          the experiment, which you can commit
  <name>.report.json   the latest evaluation report
  runs/                one folder for each evaluation run
  optimizations/       one folder for each optimization run
```

A `.gitignore` in `experiments/` keeps the run history out of git. Commit the agent file and the experiment files together.
To run the agent without dev, use `strands --agent ./agent.py`, or import its `agent` in your application.
