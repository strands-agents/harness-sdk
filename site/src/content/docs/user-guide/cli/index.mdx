You improve an agent in a loop. You change its instructions or its tools, you try it, and you compare its answers with the answers that you expect. Then you change it again.
Each pass of that loop usually needs a test set, a script that runs it, and a manual review of the results.

The Strands CLI puts that loop in your terminal. It has two commands:

- `strands` opens a chat with a [Strands harness](/docs/user-guide/harness/) agent. You configure a model provider once, and you do not write code.
- `strands dev` is the builder for Strands harness. It opens a harness project in a workspace of its own, and it reloads the agent when you change the agent files. In the same chat, it tests the agent on experiments and tunes the agent with [Strands Evals](/docs/user-guide/evals-sdk/).

## What strands dev does

`strands dev` gives each harness project a workspace: a `strands-dev/` folder next to the agent file. The workspace keeps the settings, the experiments, and the optimization runs of dev.
Your default agent for `strands` does not change.

A dev chat has three steps:

1. **Build.** Chat with the agent, and edit its source file. After each save, dev reloads the agent and keeps the conversation. When you change the model or the effort in the chat, dev writes the change into the agent file.
2. **Test.** `/experiment` makes a set of test cases from a description or from your past chats. Then it runs the agent on the cases. The report gives the passed cases, the failed cases, and the reason for each failure.
3. **Optimize.** `/optimize` tunes the instructions, the model, the effort, and other options of the harness against an experiment. You examine each proposed edit as a diff, and dev writes only the edits that you apply.

The agent file stays a usual Strands harness file. You can commit it, run it with `strands --agent`, or import its agent in your application.

## What you need

- Node.js 22.12 or later for the CLI.
- Credentials for a model provider. The default model is on Amazon Bedrock.
- Python 3.10 or later for a Python harness, and for experiments and optimization. The first evaluation installs `strands-agents-evals` in a shared Python environment.
- Access to AWS Bedrock for case generation. Generation uses its own Bedrock connection, and not the model of your chat.

Generation, evaluation, and optimization call models, and these calls can cost money. Dev starts a paid run only after your approval.
