The Strands CLI gives you a [Strands harness](/docs/user-guide/harness/) agent in your terminal, and you do not write code.
You configure a model provider once. Then the agent reads and changes files, runs shell commands, searches the web, and keeps your sessions.

```bash
npm install -g @strands-agents/cli
strands "summarize what this repo does"
```

## The agent that you get

The default agent uses Claude Opus 5 on Amazon Bedrock. It has reasoning, shell and file tools, web access, prompt caching, todos, a subagent, Agent Skills, resumable sessions, long-term memory, and automatic context management.

## The Base CLI

The agent that `strands` runs is the Base CLI. Its configuration is the saved profile in `~/.strands/cli.toml`.
Setup writes this profile, and `/setup` in a chat opens setup again. You can also ask the agent to change its own configuration, for example "use high reasoning and keep responses concise".

To make the Base CLI better with tests and measured changes, use `strands dev`. See [Improve the Base CLI](dev/base-cli/).

## When to use strands dev

Use `strands` to work with an agent. Use `strands dev` to work on an agent:

- Test the agent on a set of cases, and read why each failed case failed.
- Tune its instructions, model, effort, and other options against those cases.
- Change a harness project in code, and get a reload after each save.

`strands dev` keeps its state in a workspace of its own. Plain `strands` keeps the same default agent.
