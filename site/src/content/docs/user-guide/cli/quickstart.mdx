In this quickstart, you build a Python harness agent with `strands dev`. You make an experiment for the agent, you run the experiment, and then the optimizer proposes changes to the agent.
At the end, you have an agent file with the edits that you applied, and a report for each run.

## Before you start

- Install Node.js 22.12 or later.
- Install Python 3.10 or later. When `python3` on your path is older, set `PYTHON` to a newer interpreter.
- Get credentials for a model provider, and access to AWS Bedrock. Case generation uses Bedrock.

This quickstart makes paid model calls for the generation of cases, for the evaluation, and for the optimization.

## Install the CLI

```bash
npm install -g @strands-agents/cli
```

## Connect a model provider

Run `strands`. When setup opens, select **Quickstart**, and then select a provider and a model.
The CLI finds the credentials that you have already, for example an AWS profile. Then the chat opens. Type `/exit` to close it.

## Create a harness

Go to an empty folder, and run `strands dev`:

```bash
mkdir support-agent && cd support-agent
strands dev
```

The picker shows three groups: **Global Harness**, **Discovered Harnesses**, and **New Harness**. Select **Create a new harness**.
Type a name for the agent. The language is Python. Push Enter.

Dev creates the project and installs its dependencies in `.venv`:

```text
strands-workspace/
  agent.py        the harness agent
  strands-dev/    the workspace of strands dev
```

The chat opens. A card at the top names the workspace and the harness file.
In the background, dev installs `strands-agents-evals` in a shared Python environment the first time that it needs it. This installation can take some minutes.

## Change the agent while you chat

Ask the agent a question. Then open `strands-workspace/agent.py` in your editor. Add instructions to the `create_harness` call:

```python
from strands_harness import create_harness

agent = create_harness(
    name="support-agent",
    instructions="You answer questions about the refund policy of an online store. Answer in two sentences or less.",
)
```

Your file also has the model, session, and memory options from your saved profile. Keep them.
Save the file. Dev reloads the agent, and the status line shows `↻ agent.py reloaded · session kept`. Ask again, and compare the answer.

## Make an experiment

An experiment is a set of test cases for the agent. Type `/experiment`.
The agent asks what the experiment must test:

```text
/experiment
```

Write the topic of the cases, for example "questions about refunds, late fees, and damaged items".
The agent gives a name and a number of cases for the experiment, and it waits for your approval. Reply "yes".

The generation runs in the background, and a line below the chat input shows its progress. When it finishes, a notice gives the path of the experiment file, `strands-dev/experiments/<name>/<name>.json`.

## Run the experiment

Type `/experiment` again, and select your experiment. Then select **Run it**. The selection is your approval, and the run starts at once.

When the run finishes, a notice gives the path of the report. Type `/experiment`, select the experiment, and select **View its last report**.
The agent gives the passed cases, the total, and the score. For each failed case, it gives the reason from the evaluator.

## Optimize the agent

Type `/optimize`. The agent asks which experiment to use, which options to tune, what the run must improve, what must stay true, and the budget. For a first run, select a small budget.

The agent prints a review of the run in the chat, with the estimated rollouts and judge calls. Reply "approve" to start the run, or name a row to change it.

The run continues in the background. When it finishes, the proposed edits show on screen as a diff, one edit at a time. Select **Apply this change** or **Leave it as it is**.
When each edit has an answer, dev writes the edits that you applied into `agent.py`. Then dev reloads the agent.

To measure the change, run the experiment again from `/experiment`.

## Open the evals UI

The evals UI is a local web page for your experiments, reports, and optimization runs. When it is ready, a notice in the chat gives its link.
You can also ask the agent, for example "open the last report in the evals UI".

## What you built

You have a harness agent in `strands-workspace/agent.py`, with the edits that you applied. Its workspace keeps the experiment and the history of each run:

```text
strands-workspace/strands-dev/experiments/<name>/
  <name>.json          the experiment, which you can commit
  <name>.report.json   the latest evaluation report
  runs/                one folder for each evaluation run
  optimizations/       one folder for each optimization run
```

To run the agent without dev, use `strands --agent strands-workspace/agent.py`.
