Storage backends expose an optional
<Syntax py="search()" ts="search()" /> method that
delegates to a pluggable search strategy. A strategy
implements the
<Syntax py="SearchStrategy" ts="SearchStrategy" />
protocol/interface: given a storage backend and a query
string, it returns a ranked list of matching keys with
relevance scores.

All shipped backends default to
`KeywordSearchStrategy`. You can swap in a different
strategy at the consumer level (for example, when
configuring a memory store) or by overriding
<Syntax py="search()" ts="search()" /> in a custom
backend.

## KeywordSearchStrategy

The default strategy shipped with both SDKs. Tokenizes
the query into lowercased words, reads every key in
storage, and scores each entry by the number of distinct
query tokens that appear in the key and content. No
index, embedding model, or external dependency required.

Because it reads every entry on each search, keyword
search is best suited for small-to-medium stores (up to
a few thousand keys). For larger stores, consider a
full-text strategy.

## QmdSearchStrategy

:::note
`QmdSearchStrategy` is available in TypeScript only.
:::

BM25 full-text search powered by QMD, a SQLite-backed
inverted index. Accounts for term frequency, inverse
document frequency, and document length normalization
--- significantly better relevance ranking than keyword
overlap for large stores.

Works only with `LocalFileStorage` because it needs a
filesystem directory to index. Requires `@tobilu/qmd`
as a peer dependency:

```bash
npm install @tobilu/qmd
```

The strategy maintains a persistent SQLite index that
syncs with the backing directory before each search.
Call <Syntax ts="close()" /> when the strategy is no
longer needed to release the database connection.

## Custom strategies in FileMemoryStore

:::note
The <Syntax ts="search" /> config parameter on
`FileMemoryStore` is available in TypeScript only. In
Python, `FileMemoryStore` delegates to the storage
backend's
<Syntax py="search()" /> method; override it in a
custom backend to change the strategy.
:::

Pass a strategy to `FileMemoryStore` through its
<Syntax ts="search" /> config parameter. The store's
<Syntax ts="search()" /> delegates to it instead of
the default keyword scan, while the underlying storage
backend stays unchanged.
