As conversations grow, your agent's context window fills
with messages, tool results, and system prompts. Without
management, this leads to token limit errors, degraded
performance, and loss of relevant information.

The SDK ships context management that works out of the box.
Pick a mode and the SDK wires up an ordered strategy
pipeline with tuned defaults.

## Quick start

Pass
<Syntax
  py='context_manager="auto"'
  ts='contextManager: "auto"'
/> and the SDK manages context in the background:

<Tabs>
<Tab label="Python">

```python

agent = Agent(context_manager="auto")
```

## How it works

The
<Syntax
  py="context_manager"
  ts="contextManager"
/> parameter is a first-class agent parameter, not a
plugin. It creates a `ContextManager` that owns all
context reduction for the agent.

The ContextManager runs strategies as an ordered pipeline.
Each strategy sees the output of the previous one. The SDK
always appends an emergency truncation strategy as the
final step, which only fires when the window is still
overflowing after all other strategies have run.

A stash stores all message content on arrival as JSON,
before any strategy acts. Truncated or summarized content
is preserved and retrievable on demand through the
<Syntax
  py="retrieve_context"
  ts="retrieve_context"
/> tool, registered by default.

When
<Syntax
  py="context_manager"
  ts="contextManager"
/> is set, any co-provided
<Syntax
  py="conversation_manager"
  ts="conversationManager"
/> is ignored. The ContextManager owns overflow recovery
and proactive compression internally.

## Choosing a mode

| Value | Behavior |
|-------|----------|
| `"auto"` | Background compression with tuned defaults. No model involvement. |
| `"agentic"` | Model-driven: the model manages its own context with tools and telemetry. |
| Custom config | Full control over the strategy pipeline, targets, and conditions. |
| `false` | No context management. Overflow errors propagate directly. |

See [Built-in Modes](./context-management/built-in-modes)
for details on `"auto"` and `"agentic"`.
See [Custom Strategies](./context-management/custom-strategies)
to build your own pipeline.

## Limitations

**Stateful models.** Stateful models manage conversation
state server-side. Setting
<Syntax
  py="context_manager"
  ts="contextManager"
/> with a stateful model raises an error.

**In-memory stash.** The stash uses in-memory storage by
default, which does not persist across process restarts.
Configure a durable storage backend when using session
management. See
[Custom Strategies](./context-management/custom-strategies#stash).
