Strands harness's built-in contract already handles how the agent behaves; your `instructions` tell
it who it is and what it is for, and your `tools` give it the capabilities your
application needs. Both add to the built-ins rather than replacing them.

## Add instructions

You tell the agent who it is with `instructions`, a domain block appended after the
built-in contract: the agent's identity, scope, and any rules you want it to follow. The
harness's contract handles the general "how to act like an agent" behavior, so keep
`instructions` to what is specific to your use case.

<Tabs>
  <Tab label="Strands harness">
    <Tabs>
      <Tab label="Python">
        ```python
        from strands_harness import create_harness

        agent = create_harness(
            instructions="You are a support assistant. Always link the ticket you acted on.",
        )
        ```
      </Tab>
      <Tab label="TypeScript">
        ```typescript
        import { createHarness } from '@strands-agents/harness'

        const agent = await createHarness({
          instructions: 'You are a support assistant. Always link the ticket you acted on.',
        })
        ```
      </Tab>
    </Tabs>
  </Tab>
  <Tab label="SDK">
    <Tabs>
      <Tab label="Python">
        ```python
        # pip install strands-agents
        from strands import Agent

        agent = Agent(
            system_prompt="You are a support assistant. Always link the ticket.",
        )
        ```
      </Tab>
      <Tab label="TypeScript">
        ```typescript
        // npm install @strands-agents/sdk
        import { Agent } from '@strands-agents/sdk'

        const agent = new Agent({
          systemPrompt: 'You are a support assistant. Always link the ticket.',
        })
        ```
      </Tab>
    </Tabs>
  </Tab>
</Tabs>

If you pass a full `system_prompt` through to the `Agent` instead, `instructions` is
ignored: the prompt you supply replaces the contract entirely. To build on the contract
programmatically, see [compose with the Strands Harness SDK](../../composing-with-sdk/).

## Register your own tools

You give the agent your own capabilities by passing `tools`, which sit alongside the
built-in ones. Define them the same way you would for any Strands agent:

<Tabs>
  <Tab label="Python">
    ```python
    from strands import tool
    from strands_harness import create_harness

    @tool
    def get_ticket(ticket_id: str) -> str:
        """Fetch a support ticket by id."""
        return f"Ticket {ticket_id}: open, assigned to support."

    agent = create_harness(
        instructions="You are a support assistant. Always link the ticket.",
        tools=[get_ticket],
    )
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { tool } from '@strands-agents/sdk'
    import { z } from 'zod'
    import { createHarness } from '@strands-agents/harness'

    const getTicket = tool({
      name: 'get_ticket',
      description: 'Fetch a support ticket by id.',
      inputSchema: z.object({ ticketId: z.string() }),
      callback: ({ ticketId }) => `Ticket ${ticketId}: open, assigned to support.`,
    })

    const agent = await createHarness({
      instructions: 'You are a support assistant. Always link the ticket.',
      tools: [getTicket],
    })
    ```
  </Tab>
</Tabs>

A tool name must be unique across every source (built-in tools, `tools`, and plugin-vended
tools). A collision fails at construction and names
the two sources, so nothing silently disappears. To reuse a built-in's name, drop the
built-in first.

## Select or disable built-in tools

The built-in tools are `shell`, `read`, `write`, `edit`, `web_fetch`, `web_search`,
`programmatic_tool_caller`, and `subagent`, all on by default. Pass `builtin_tools` a subset to narrow the
set, or an empty list to turn them all off and bring your own:

<Tabs>
  <Tab label="Strands harness">
    <Tabs>
      <Tab label="Python">
        ```python
        from strands_harness import create_harness

        agent = create_harness(builtin_tools=["read", "shell"])  # just these two; [] for none
        ```
      </Tab>
      <Tab label="TypeScript">
        ```typescript
        import { createHarness } from '@strands-agents/harness'

        const agent = await createHarness({ builtinTools: ['read', 'shell'] }) // [] for none
        ```
      </Tab>
    </Tabs>
  </Tab>
  <Tab label="SDK">
    <Tabs>
      <Tab label="Python">
        ```python
        # pip install strands-agents
        from strands import Agent
        from strands.vended_tools import file_editor, shell

        # The Strands Harness SDK has no built-in toggle; pass exactly the tools you want
        agent = Agent(tools=[file_editor, shell])
        ```
      </Tab>
      <Tab label="TypeScript">
        ```typescript
        // npm install @strands-agents/sdk
        import { Agent } from '@strands-agents/sdk'
        import { bash } from '@strands-agents/sdk/vended-tools/bash'
        import { fileEditor } from '@strands-agents/sdk/vended-tools/file-editor'

        // The Strands Harness SDK has no built-in toggle; pass exactly the tools you want
        const agent = new Agent({ tools: [fileEditor, bash] })
        ```
      </Tab>
    </Tabs>
  </Tab>
</Tabs>

An unknown name fails at construction with the list of valid names. For what each tool
does, see [shell and file tools](../../tools/shell-and-files/),
[web access](../../tools/web-access/), and
[programmatic tool calling](../../tools/programmatic-tool-calling/).

## Edit the default tool set

To keep the defaults but drop or configure one tool, pass
<Syntax py="builtin_tools" ts="builtinTools" /> a mapping instead of a list. A list pins the
set to exactly the names given. A mapping edits the default set:
<Syntax py="False" ts="false" /> removes a tool, <Syntax py="True" ts="true" /> adds one, and a
config object enables and configures it. Every tool the mapping does not name keeps its
default, so a mapping that only sets `read` to <Syntax py="True" ts="true" /> still enables
`shell`, `write`, `edit`, and the rest. To start from an empty set, set the `"*"` key to
<Syntax py="False" ts="false" /> and name only the tools you want:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    # Every default except subagent
    agent = create_harness(builtin_tools={"subagent": False})

    # Only read and web_fetch, with web_fetch configured; the same set as ["read", "web_fetch"]
    pinned = create_harness(
        builtin_tools={"*": False, "read": True, "web_fetch": {"transport": "direct"}},
    )
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'

    // Every default except subagent
    const agent = await createHarness({ builtinTools: { subagent: false } })

    // Only read and web_fetch, with web_fetch configured; the same set as ['read', 'web_fetch']
    const pinned = await createHarness({
      builtinTools: { '*': false, read: true, web_fetch: { transport: 'direct' } },
    })
    ```
  </Tab>
</Tabs>

An empty mapping changes nothing and leaves every default on. Use an empty list to turn every
built-in tool off.

## Turn off tools that other features add

<Syntax py="builtin_tools" ts="builtinTools" /> controls only the built-in tools listed above.
Other features that are on by default give the agent their own tools, so an agent built with an
empty list can still offer the model these. Each one has its own switch:

| Tool | Added by | Turn off with |
|---|---|---|
| `retrieve_context`, `retrieve_offloaded_content` | [Context management](../context-and-caching/) | <Syntax py="context_manager=False" ts="contextManager: false" /> |
| `strands_manage_background_task` | [Background tasks](../background-tasks/) | <Syntax py="background_tasks=False" ts="backgroundTasks: false" /> |
| `todo_write` | The `todos` [built-in plugin](../../tools/todos-and-environment/) | <Syntax py="builtin_plugins" ts="builtinPlugins" /> without `todos` |
| `search_memory` | [Long-term memory](../memory/) | <Syntax py="memory=False" ts="memory: false" /> |
| `skills` | [Agent Skills](../skills/), when a skill is found | <Syntax py="skills=False" ts="skills: false" /> |

With all of these off and an empty built-in tool list, the agent has only the tools you pass
in <Syntax py="tools" ts="tools" />, the tools your own plugins add, and the tools your MCP
servers provide.

## Change the web_fetch summarizer

`web_fetch` answers over a fetched page using a small, fast summarizer model chosen for
your main provider so credentials line up. Override it with `{"web_fetch": {"model": ...}}` in `builtin_tools`, which takes
the same forms as `model`. This is covered on the
[web access](../../tools/web-access/) page.

For the full option list, see the
[configuration reference](../../reference/configuration/).
