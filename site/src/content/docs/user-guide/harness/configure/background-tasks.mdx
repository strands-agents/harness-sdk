Background tasks let a tool run while the agent keeps working, instead of blocking the
agent loop until it finishes. Strands harness enables them by default. Configure them
through <Syntax py="background_tasks" ts="backgroundTasks" /> when you create the harness.

This is a Strands Harness SDK capability. For task states, result delivery, and
cancellation, see [run tools in the background](../../sdk/tools/background-tasks.md).

## What runs in the background by default

- The built-in [`subagent` tool](../subagents/), which runs the `generalist` delegate,
  always runs in the background, so the main agent continues while the delegate works.
- For any other compatible tool, the model chooses foreground or background execution.
- An invocation waits for background results and continues with them before returning.

The default policy is `agentic: ["*"]`, to which the harness adds `subagent` as an
`always` tool.

## Tune the policy

Pass a policy object to control which tools may run in the background, along with
concurrency, timeouts, and whether invocations wait. This configuration keeps other
tools in the foreground and lets two delegates run at once:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    agent = create_harness(
        background_tasks={
            "never": ["*"],
            "max_concurrency": 2,
        },
    )
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'

    const agent = await createHarness({
      backgroundTasks: {
        never: ['*'],
        maxConcurrency: 2,
      },
    })
    ```
  </Tab>
</Tabs>

With any policy, `subagent` still runs in the background. The harness adds it to
`always` and removes it from your `agentic` and `never` lists. A wildcard such as
`never: ["*"]` stays in place, and the exact `subagent` rule takes precedence over it.

To let an invocation return while work is still running, set
<Syntax py="wait_for_completion" ts="waitForCompletion" /> to
<Syntax py="False" ts="false" /> in the policy. Your application then invokes the same
agent again to deliver the results. See
[return while tasks are still running](../../sdk/tools/background-tasks.md#return-while-tasks-are-still-running).

An interrupt raised inside a backgrounded delegate fails that task instead of pausing
the agent. That includes an [interventions](../interventions/) approval for one of the
delegate's tool calls; approval for the `subagent` call itself still pauses the agent.
If your delegates need to ask for approval, disable background tasks.

## Disable background tasks

Pass <Syntax py="False" ts="false" /> to run every tool in the foreground,
including `subagent`:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    agent = create_harness(background_tasks=False)
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'

    const agent = await createHarness({ backgroundTasks: false })
    ```
  </Tab>
</Tabs>

## Cancel background work

`agent.cancel()` stops the current invocation but leaves background tasks running.
To stop them too, ask for it in the same call:

<Tabs>
  <Tab label="Python">
    ```python
    agent.cancel(cancel_background_tasks=True)
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    agent.cancel({ cancelBackgroundTasks: true })
    ```
  </Tab>
</Tabs>

If the invocation had already finished its turn and was only waiting for background
tasks, it returns that turn's result, and the cancelled task results are delivered on
the next invocation.

## The CLI

The Strands harness CLI runs on the TypeScript library, so `subagent` runs in the
background there too. Its interactive terminal goes one step further and doesn't wait
for background work: a turn can finish while tasks run, you can enter another prompt,
and the CLI starts a new turn to deliver each result when it's ready. `/tasks` shows
your todos and background tasks.

Print and plain modes wait for background work before they return. The CLI has no
dedicated flag for the background-tasks policy. To turn background tasks off, use the
setup wizard (`strands --setup`) or pass `--set agentConfig.backgroundTasks=false` for
one run. Use the library when you need to tune the policy.

For the full option list, see the
[configuration reference](../../reference/configuration/).
