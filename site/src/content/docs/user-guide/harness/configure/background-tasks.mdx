Background tasks let a tool run while the agent keeps working, instead of blocking the
loop until it finishes. This is a Strands Harness SDK capability, exposed through Strands harness's
`background_tasks` / `backgroundTasks` option.

## What runs in the background by default

The built-in `generalist`
[delegate](../subagents/) always runs in the background, so
the main agent can continue while the delegate works through its subtask. By default the
model may also choose background execution for any other compatible tool; the invocation
waits for the result and continues with it.

## Tune or disable it

`backgroundTasks` accepts a boolean or a policy object. Pass `false` to disable background
tasks, or a policy to control which tools may run in the background, along with
concurrency, completion, and timeouts. With a policy, the `generalist` still runs in
the background: Strands harness forces it there and merges that into your policy.

```typescript
import { createHarness } from '@strands-agents/harness'

// Disable background tasks:
const noBackground = await createHarness({ backgroundTasks: false })

// Or supply a policy for the other tools:
const scoped = await createHarness({
  backgroundTasks: { agentic: ['long_running_report'] },
})
```

The default policy is equivalent to `{ agentic: ['*'] }`: the model may run any compatible
tool in the background.

## Cancel background work

`agent.cancel()` stops the current invocation but leaves background tasks running. To stop
them too, pass `cancelBackgroundTasks`:

```typescript
agent.cancel({ cancelBackgroundTasks: true })
```

If the invocation had already finished its turn and was only waiting for background tasks, it
returns that turn's result, and the cancelled task results are delivered on the next invocation.

## Choose the management tool name

The model lists, reads, and cancels background tasks through a tool named
`manage_background_task`. Use that name when a hook or tool-choice setting refers to it.
Finished tasks are delivered as calls to this tool, so the name is also written into
conversation history.

To change it, set
<Syntax py="background_tasks.manage_tool_name" ts="backgroundTasks.manageToolName" />.
Agents built directly on the Strands Harness SDK default to
`strands_manage_background_task`. Set that value to resume a session saved under it,
because existing messages keep the name they were written with.

## The CLI

The Strands harness CLI runs on the TypeScript library, so the `generalist` runs in the background
there too. Its management tool is named `strands_manage_background_task`. The CLI does not
expose a flag to change the background-tasks policy; use the library when you need to tune it.

For the full option list, see the
[configuration reference](../../reference/configuration/).
