Background tasks let a tool run while the agent keeps working, instead of blocking the
agent loop until it finishes. Strands harness enables them by default. Configure them
through <Syntax py="background_tasks" ts="backgroundTasks" /> when you create the harness.

For the underlying SDK feature, including task lifecycle, cancellation, and result
delivery, see [Background tasks](../../sdk/tools/background-tasks.md).

## Understand the defaults

- The built-in [`subagent` tool](../subagents/) always runs in the background.
- For other compatible tools, the model chooses foreground or background execution.
- A library invocation waits for background results and continues with them before
  returning, unless you change <Syntax py="wait_for_completion" ts="waitForCompletion" />.

The default policy allows model-selected background execution for all compatible tools
with `agentic: ["*"]`, then adds `subagent` to `always`. The interactive CLI changes the
return behavior, as described below.

## Choose which tools run in the background

Pass a policy object to control tools, concurrency, timeouts, and result delivery.
For example, this configuration keeps other tools in the foreground and allows up to two
background subagent tasks to execute at once:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    agent = create_harness(
        background_tasks={
            "never": ["*"],
            "max_concurrency": 2,
        },
    )
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript

    --8<-- "user-guide/harness/configure/background-tasks.ts:background_policy"
    ```
  </Tab>
</Tabs>

The harness keeps `subagent` in `always` whenever background tasks are enabled. It removes
explicit `subagent` entries from your `agentic` and `never` lists. A wildcard such as
`never: ["*"]` stays in place, but the exact `subagent` rule takes precedence.

To let a library call return while work is still running, set
<Syntax py="wait_for_completion" ts="waitForCompletion" /> to
<Syntax py="False" ts="false" /> in the policy. Your application must invoke the same
agent again to deliver results to its conversation. See
[delivery](../../sdk/tools/background-tasks.md#return-while-tasks-are-still-running)
for the full flow.

## Disable background tasks

Pass <Syntax py="False" ts="false" /> to disable background execution for every tool,
including `subagent`:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    agent = create_harness(background_tasks=False)
    ```

## Cancel background work

`agent.cancel()` stops the current invocation but leaves background tasks running. To stop
them too, pass `cancelBackgroundTasks`:

```typescript
agent.cancel({ cancelBackgroundTasks: true })
```

If the invocation had already finished its turn and was only waiting for background tasks, it
returns that turn's result, and the cancelled task results are delivered on the next invocation.

## Use background tasks in the CLI

The interactive Ink CLI uses detached execution by default: the current turn can finish
while background tasks keep running, and you can enter another prompt. When results are
ready, the CLI starts a continuation turn to deliver them automatically.

Open `/tasks` to inspect tasks and live subagent progress. Its wait-mode switch rebuilds
the agent with <Syntax py="wait_for_completion" ts="waitForCompletion" /> enabled, so
invocations wait for background results before returning. You cannot switch modes while
background tasks or undelivered results remain.

Plain, print, and ACP server modes use the normal library wait behavior. To configure
which tools run in the background, use the harness library's policy option.

For the full option list, see the
[configuration reference](../../reference/configuration/).
