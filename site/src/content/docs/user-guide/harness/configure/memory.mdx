Long-term memory lets the agent recall durable facts across conversations without you
re-supplying them. Strands harness keeps it on by default: it distills facts into markdown files,
searches them before each model call, and folds the top matches into context. Persistence is
plain files, independent of any session, so memory survives across sessions and works with
sessions off.

## What memory does by default

With memory on, Strands harness runs a memory manager over a file-backed store under
`./.agent/memory`. Before each model call it searches that store and injects the most relevant
entries, and the agent also gets a `search_memory` tool for on-demand recall. Extraction,
distilling durable facts from the conversation, runs in the background every few turns on a
small, credential-aligned model, so keeping memory costs little.

## Change when memory is recalled

How often memory is recalled sets what it costs. Strands harness recalls before every
model call, not only when the user sends a message, so each step of a tool loop sees
relevant memory. A task that takes ten model calls can run ten searches, each injecting up
to five entries; with the default file store, each entry is a whole topic file. The
injected text sits after the cached prompt prefix, so you pay for it as fresh input tokens
on every call.

To recall less often, build a memory manager yourself and pass it as `memory`. Strands
harness uses it as-is. This one recalls only when the user sends a message and injects at
most two entries:

<Tabs>
  <Tab label="Python">
    ```python
    from strands.memory import MemoryInjectionConfig, MemoryManager
    from strands.vended_memory_stores.file_memory_store import FileMemoryStore
    from strands_harness import create_harness

    memory = MemoryManager(
        stores=[FileMemoryStore(name="memory", extraction=True)],
        injection=MemoryInjectionConfig(trigger="userTurn", max_entries=2),
    )
    agent = create_harness(memory=memory)
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'
    import { MemoryManager } from '@strands-agents/sdk'
    import { FileMemoryStore } from '@strands-agents/sdk/vended-memory-stores/file-memory-store'

    const memory = new MemoryManager({
      stores: [new FileMemoryStore({ name: 'memory', extraction: true })],
      injection: { trigger: 'userTurn', maxEntries: 2 },
    })
    const agent = await createHarness({ memory })
    ```
  </Tab>
</Tabs>

To stop automatic recall and keep only the `search_memory` tool, set
<Syntax py="injection=False" ts="injection: false" /> instead. The agent then reads memory
only when it calls the tool.

A manager you build owns its store, so the harness defaults no longer apply to it: this
`FileMemoryStore` uses the SDK's default location, and extraction runs on the agent's
model rather than the harness's small model. The `generalist` delegate gets no memory from
a manager passed this way. For every injection option, see
[context injection](../../../sdk/memory/managing-memory/#context-injection).

## Move the memory files

Set `memory={"dir": ...}` to store the memory files somewhere other than `./.agent/memory`:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    agent = create_harness(memory={"dir": "/var/lib/agent/memory"})
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'

    const agent = await createHarness({ memory: { dir: '/var/lib/agent/memory' } })
    ```
  </Tab>
</Tabs>

## Swap the memory backend

To keep facts somewhere other than local files, pass your own memory store (or several)
as `memory={"stores": [...]}`. Strands harness still owns the manager, so its policy holds: injection on,
`search_memory` on, and no write tool. This is the seam for a non-file backend without
giving up Strands harness's defaults:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness
    from my_stores import PostgresMemoryStore

    agent = create_harness(memory={"stores": [PostgresMemoryStore(dsn="postgres://...")]})
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'
    import { PostgresMemoryStore } from './my-stores'

    const agent = await createHarness({ memory: { stores: [new PostgresMemoryStore('postgres://...')] } })
    ```
  </Tab>
</Tabs>

The `generalist` delegate shares these stores read-only, so it recalls the same memory but
never writes throwaway subtask noise into it. To replace the manager wholesale, pass a full
`memory_manager` through to the `Agent` instead; that owns its own stores and Strands harness steps
aside.

## Turn memory off

Pass `False`/`null` (or set `memory` off) to disable memory entirely:

<Tabs>
  <Tab label="Python">
    ```python
    from strands_harness import create_harness

    agent = create_harness(memory=False)
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    import { createHarness } from '@strands-agents/harness'

    const agent = await createHarness({ memory: false })
    ```
  </Tab>
</Tabs>

## Flush before a short run exits

Extraction is background and turn-triggered, so a short run can end with its latest turns
not yet written. The simplest way to persist what is pending is to scope the agent so its
shutdown runs when the block exits — on a normal return and on a thrown error alike:

<Tabs>
  <Tab label="Python">
    ```python
    async with create_harness() as agent:
        await agent.invoke_async(task)
    # the agent's shutdown runs here as the scope exits, flushing pending memory
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    await using agent = await createHarness()
    await agent.invoke(task)
    // the agent's shutdown runs here as the scope exits, flushing pending memory
    ```
  </Tab>
</Tabs>

If you manage the agent's lifetime yourself, run its shutdown at your shutdown boundary:

<Tabs>
  <Tab label="Python">
    ```python
    agent.shutdown()  # or `await agent.shutdown_async()` from async code
    ```
  </Tab>
  <Tab label="TypeScript">
    ```typescript
    await agent.shutdown()
    ```
  </Tab>
</Tabs>

The [Strands harness CLI](../../quickstart/#build-an-agent-with-the-cli) already flushes at the process boundary; a
library consumer should do the same. For the memory manager and stores, see the Strands Harness SDK's
[long-term memory](../../../sdk/memory/overview/) documentation. For the full
option list, see the
[configuration reference](../../reference/configuration/).
