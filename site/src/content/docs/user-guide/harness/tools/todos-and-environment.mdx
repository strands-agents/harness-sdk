Two of Strands harness's built-ins are plugins rather than tools: `environment` and
`todos`. Both are selected through `builtin_plugins` and shape how the agent works without
being things the model calls the way it calls `shell` or `read`. `environment` is on by
default; `todos` is opt-in.

## todos

:::caution[Moving to the SDK]
The harness `todos` built-in is deprecated. The plugin now ships in the SDK as
`Todos`, so construct it yourself and pass it in `plugins` — see the SDK tab below.
Constructing the harness built-in warns, and it is removed in a later harness minor.
[Track the move](https://github.com/strands-agents/harness-sdk/issues/5279).
:::

The `todos` plugin gives the agent a `todo_write` tool and keeps the current task list in
view. When the agent writes a list, the plugin re-surfaces it to the model before each
step, so on a longer task the agent keeps its plan in front of it without restating it.

The list lives in agent state. Each rendered copy is injected into the conversation as an
`injected` block, and only the latest user message's injected blocks are sent to the model
— older ones are dropped from the request, so a constantly-changing plan never reaches the
model as a stack of stale copies. Each item has a `content` (the task, imperative), an
`activeForm` (shown while it is in progress), and a `status` of `pending`, `in_progress`,
or `completed`. The agent is guided to keep one item in progress at a time and clear the
list when the work is done.

`todos` is opt-in. Because it re-injects the list on every turn, it costs tokens and moves
the cached prefix boundary on providers without explicit cache points, so enable it where
the task tracking earns that.

## environment

The `environment` plugin injects a small block of working-environment context before each
user turn:

- The platform and the current date.
- The working directory.
- The project's `AGENTS.md`, included in full up to a cap (about 16 KB); a longer file is
  truncated with a marker, and the agent can read the rest on demand.
- Links (not contents) to other `AGENTS.md` and `README.md` files found a couple of levels
  down, so the block stays small and the agent reads them only as needed.

Everything is read through the agent's [sandbox](../../../sdk/sandbox/), so
the platform, directory, and files describe where the agent actually runs. The date is
injected each turn (rather than baked into the system prompt) precisely so it does not
change the cached prompt prefix; the rest is discovered once and reused.

## Select or disable them

`builtin_plugins` selects these by name, defaulting to `["environment"]`. Name both to add
todos, or pass an empty list to turn both off:

<Tabs>
  <Tab label="Strands harness">
    <Tabs>
      <Tab label="Python">
        ```python
        from strands_harness import create_harness

        agent = create_harness(builtin_plugins=["todos", "environment"])
        ```
      </Tab>
      <Tab label="TypeScript">
        ```typescript
        import { createHarness } from '@strands-agents/harness'

        const agent = await createHarness({ builtinPlugins: ['todos', 'environment'] })
        ```
      </Tab>
    </Tabs>
  </Tab>
  <Tab label="SDK">
    <Tabs>
      <Tab label="Python">
        ```python
        # pip install strands-agents
        from strands import Agent
        from strands.vended_plugins.todos import Todos

        agent = Agent(plugins=[Todos()])
        ```
      </Tab>
      <Tab label="TypeScript">
        ```typescript
        // npm install @strands-agents/sdk
        import { Agent } from '@strands-agents/sdk'
        import { Todos } from '@strands-agents/sdk/vended-plugins/todos'

        const agent = new Agent({ plugins: [new Todos()] })
        ```
      </Tab>
    </Tabs>
  </Tab>
</Tabs>
