# Divergences from strands-ts

User-visible differences between the Rust harness and harness-ts at `7296caba7`. Each entry says what differs, why, and confirms that no cross-SDK wire or persisted format changes.

Rust-native differences that the design calls for (string slicing by `char`, `Result` instead of exceptions, compile-time rejection of concurrent invocation) are not listed.

| Area | Difference | Reason | Wire impact |
|---|---|---|---|
| model strings | `google/`, `ollama/` and `litellm/` fail with `model provider "<p>" is not supported in Rust yet`; the unknown-provider message lists the four Rust providers; a provider whose cargo feature is off fails with `model '<spec>' requires the strands-harness feature "<f>"` (the harness features share the `strands` names) | These providers come later ([RFC: v0.1 providers](../../team/designs/0022-rust-sdk.md#decision-v01-providers)); cargo features replace peer dependencies | None |
| Cedar interventions | Without the `cedar` feature a `.cedar` value fails with `Cedar policy '<p>' needs the strands-harness feature "cedar"; enable it to use Cedar interventions.` | Cargo feature instead of the optional npm dependency | None |
| portable config | Module references parse and round-trip, but `harness_agent_options_from_config` fails on the first one with `module references are not supported in Rust yet` (plus ` (language "<l>")`); an explicit `allowedTools: null` normalizes to an absent key | Loading TS or Python modules has no Rust equivalent yet ([RFC: portable config](../../team/designs/0022-rust-sdk.md#decision-portable-config)); `allowedTools` absent and `null` mean the same | None: the JSON both runtimes read is unchanged |
| portable config | `agentConfig` applies `id`, `systemPrompt`, `printer`, `appState`, `modelState` and `messages`; other keys are warned about and ignored | Rust options are typed; TS spreads arbitrary keys into the SDK config | None |
| sandbox tools | Tools a sandbox vends are dropped after initialization only when the harness did not register that name itself | TS bug ([#6433](https://github.com/strands-agents/harness-sdk/issues/6433)): harness-ts drops its own tool when a sandbox vends the same name | None |
| background tasks | `background_tasks: Toggle::On(BackgroundTasksConfig::default())` is treated as `true` (agentic `*`); TS treats an empty config object as a policy with no agentic selector | `Toggle` folds `true` into the default config | None |
| sessions | A harness-built session writes compact JSON through `LocalFileStorage::new(dir).namespace("")`, the same paths as harness-ts's `FileStorage(dir)` | Same paths as harness-ts, so sessions resume across SDKs ([RFC: harness session layout](../../team/designs/0022-rust-sdk.md#decision-harness-session-layout)) | None: snapshots parse in both |
| tracing | With `OTEL_TRACES_EXPORTER` set and no global `tracing` subscriber, the harness installs one with only the SDK's OpenTelemetry layer; when the program already installed a global subscriber, the harness wires nothing and warns that the program should add `TracerGuard::layer` | The SDK's spans are `tracing` spans and reach OpenTelemetry only through a subscriber layer; replacing the program's subscriber would take over its logging | None |
| `supports_media` | A model instance is judged by its model id with the Bedrock rule (`openai.` family means no media), so an OpenAI-on-Mantle instance reads as text-only; TS checks `instanceof BedrockModel` | No downcasting in Rust | None |
| edit replacement | `edit` inserts `new_str` literally; harness-ts's `String.replace` expands `$$`, `$&`, `` $` `` and `$'` in it | TS bug ([#6432](https://github.com/strands-agents/harness-sdk/issues/6432)): harness-ts `edit` expands `$` replacement patterns in `new_str` | None |
| read paths | Text slicing counts chars; `read` has no byte caps (as harness-ts) and reads text lossily, as `readText` | Rust strings | None |
| web_fetch | Network errors on the direct transport carry reqwest's message (the `HTTP <status> <reason>` and timeout texts match); an unknown transport is a deserialization error | reqwest replaces undici; `WebFetchTransport` is an enum | None |
| web_fetch | With no summarizer resolved, the tool falls back to the calling agent's `aux_model` (its model by default) | TS always passes a resolved model; the cross-SDK aux-model rule | None |
| web_search | Exa failures carry the SDK `McpClient` error text where TS has the MCP SDK's | Different MCP client | None |
| programmatic_tool_caller | Inner calls run with the invocation's shared `InvocationState`, not a copy | `ToolAgent::call_tool_without_interrupts` takes no invocation state | None |
| programmatic_tool_caller | A denied inner call reaches the code as `Tool '<n>' error: <text>`, without TS's `Failed to execute tool '<n>': ` prefix; refused approvals and tool interrupts carry the TS prefix and text | A deny comes back from the SDK pipeline as an error result, indistinguishable from a tool error | None |
| programmatic_tool_caller | `eval` exists (sandboxed); harness-ts at the pin raises `NameError` | monty 1.5 behaviour | None |
| programmatic_tool_caller | The interpreter runs in a `monty` 1.5.0 worker subprocess (`monty-pool`) found through `Isolation`: `Isolation::Subprocess` (TS `binaryPath`), else `MONTY_BIN`, `monty` on `PATH`, then a `target/{debug,release}` build in the executable's cargo workspace, the `@pydantic/monty` order without its npm platform package. Installed with `cargo install monty-runtime --version 1.5.0 --locked` | TS ships its worker as a native addon and a platform package; a library cannot ship or re-exec a binary ([RFC: programmatic tool caller isolation](../../team/designs/0022-rust-sdk.md#decision-programmatic-tool-caller-isolation)) | None |
| programmatic_tool_caller | Without a worker binary the interpreter runs in-process, with a warning that it has no crash isolation and no cap on its total memory; TS falls back to in-process WebAssembly only when its native addon fails to load (an unsupported platform, `--omit=optional`, a broken install) | Rust cannot install the binary for the user, so a missing worker is the common case; failing every run would make the default harness unusable until it is installed | None |
| programmatic_tool_caller | In-process, the 256 MiB memory limit only bounds single allocations (500 MiB in five 100 MiB strings succeeds); in a worker it caps the process total. TS caps in-process guest time lower (`WASM_MAX_DURATION_SECS`), Rust keeps 60 s because its steps run off the runtime and a timeout returns at once | Without `monty-alloc` as the global allocator the VM checks allocation sizes only; installing it in-process would cap and kill the whole host | None |
| programmatic_tool_caller | A keyword argument or tool result nested more than 128 levels deep raises `TypeError: <f>() argument is nested more than 128 levels deep` or `RuntimeError: Tool '<n>' returned a result nested more than 128 levels deep` | Bounds the host-side conversion recursion; TS converts through the addon | None |
| programmatic_tool_caller | Inner call ids are `<toolUseId>:call:<n>`, not `ptc_<uuid>` | SDK `call_tool` numbering | None |
| subagent | A `ModelRouter` cannot be a preset or `Choice` model value | `SpecValue` holds model instances and strings | None |
| `OPENAI_BASE_URL` | The harness passes `OPENAI_BASE_URL` to the OpenAI provider as its base URL (Bedrock Mantle excluded); the SDK reads the same variable itself | Keeps the environment injectable in tests | None |
| `mcp_servers` | `HarnessAgentOptions::mcp_servers` takes `McpServersOption` (a path, a JSON map, or with `mcp` an SDK `McpServersSource`); without the `mcp` feature, setting it fails at `create_harness` with `mcp_servers needs the strands-harness feature "mcp"; enable it to connect MCP servers.` | One options struct across feature sets | None |
| built-in plugins | There is no `todos` built-in plugin and no harness `Todos` export: `builtinPlugins: ["todos"]` fails like any unknown name (`Unknown built-in plugin "todos". Available: environment.`); pass the SDK's `strands::vended_plugins::todos::Todos` in `plugins` instead | harness-ts keeps the deprecated built-in with a warning; the Rust crates are unreleased, so they carry no deprecated items | None: a portable config naming `todos` is rejected rather than read differently |

## Names

Renamed, Rust-only and unported public names. Renamed: `ToolConfig<C>` is `Setting<C>`; `Option` (subagent) is `ChoiceOption` ([RFC: prelude clash renames](../../team/designs/0022-rust-sdk.md#decision-prelude-clash-renames)); `PresetOptions` is the `Preset` builder; `MakeWebFetchOptions` is the arguments of `web_fetch_tool(config, summarizer)`; `read`, `write`, `edit` are `read_tool(media)`, `write_tool()`, `edit_tool()`; `exaWebSearch` is `web_search_tool()` (`mcp`), `makeExaWebSearch` is `search_tool(Arc::new(ExaBackend::new(key).with_url(..)))`; `mcpServers: string | McpServersConfig` is `McpServersOption`. The subagent types (`AgentSpec`, `Choice`, `ChoiceOption`, `Fixed`, `Inherit`, `Open`, `Preset`, `MakeSubagentOptions`, `SubagentTool`, `make_subagent`) are re-exported from `strands`, as harness-ts re-exports them from the SDK; its `AgentBuilder` is the SDK's `ChildAgentBuilder`. Rust-only: `McpServersMode` is public, because a public field takes it (harness-ts defines it without exporting it); `Isolation`, `MONTY_WORKER_VERSION` and `MONTY_WORKER_ENV` (`tools::programmatic_tool_caller`), `SearchBackend`/`SearchResult`/`WebSearchError` (`tools::web_search`). Not ported: `configureLogging` (a `tracing` subscriber replaces it). Harness limits, URLs and texts that harness-ts keeps out of `index.ts` (`USER_AGENT`, `MAX_BYTES`, `MAX_CHARS`, `WEB_FETCH_DESCRIPTION`, `EXA_MCP_URL`, `EXA_TOOL`, `MAX_CONCURRENT_TOOL_CALLS`, `AGENTS_MD_CAP`, `DEFAULT_SUBAGENT_MAX_DEPTH`, `BUILTIN_TOOL_CONFIG_KEYS`) are crate-private.
